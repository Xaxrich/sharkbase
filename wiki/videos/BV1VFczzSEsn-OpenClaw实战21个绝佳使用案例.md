# OpenClaw实战：21个绝佳使用案例

## 一句话摘要

一个 OpenClaw 用户的 21 个实战用例清单——从 CRM、知识库到安全审计和饮食追踪——展示了当 Agent 渗透生活每个角落时的完整生产力图景。

## 核心观点

- **用例的复利效应**：每个用例不是孤立的，而是相互增强——CRM 数据喂入每日简报，知识库内容触发视频选题管线，社交数据驱动商业顾问 council，系统整体远大于部分之和
- **安全是第一优先级而非附加**：确定性代码清洗外部数据 + 隔离权限 + 混合防御（确定性 + 非确定性），承认"不完美但尽力"
- **Agent 的自我进化是可工程化的**：从行动项审批学习过滤、到夜间安全 council 自动巡检、到自动检查更新，自我改进不再是偶然而是系统设计
- **模型特定提示工程**：不同模型提示风格截然相反（Opus 不喜欢全大写，GPT 欢迎），必须为每个模型维护独立提示指南
- **全量备份 + 加密是非 negotiable**：每小时 Git sync、加密 SQLite 备份到 Google Drive、失败立即告警——一旦失去这台机器，所有工作归零

## 详细笔记

### OpenClaw 基础架构

- 开源框架，本地运行，接入已有聊天工具（WhatsApp/Telegram/Slack/短信）
- 两个核心配置文件：`identity.md`（身份定义）和 `soul.md`（人格特质——回复风格、幽默度、正式程度）
- 记忆系统：每日笔记 → 蒸馏偏好存入 `memory.md` → 下次会话读取 → 更新身份文件；所有文件向量化支持 RAG 搜索
- 可选记忆方案：QMD（Shopify 创始人开发）、Superme（外部服务），作者偏好全本地

### 用例1：个人 CRM

- 数据源：Gmail + Google Calendar + Fathom（会议转录）
- 流程：扫描 → 过滤噪音（营销邮件/冷推销）→ LLM 判断联系人价值 → 存入本地 SQLite（含向量列）→ 自然语言查询
- 关系健康评分、跟进提醒、待办事项自动创建、重复联系人检测与合并建议
- 跨系统关联：视频选题时可能提示"你跟某赞助商聊过类似话题"

### 用例2：会议行动项管线

- Fathom 每5分钟拉取转录（仅工作时间、日历感知）
- 匹配 CRM 联系人 → 提取行动项 → Telegram 审批 → 批准后同步 Todoist
- **自学习机制**：拒绝的行动项会触发 prompt 更新，下次过滤更准
- 同时追踪对方的行动项（"他说会发你什么"→ 记录 → 检查是否完成）
- 每日3次完成度检查，14天以上自动归档

### 用例3：个人知识库

- 通过 Telegram 投入 URL（文章/视频/X 帖子/PDF）
- 自动抓取内容 → 分块 → 向量化 → 存入本地
- X/Twitter 抓取链：fxtwitter API → X API 直连 → X Search，逐级回退；自动跟踪线程全文和外部链接
- 团队共享：入库内容自动转发到 Slack 供团队阅读
- 支持自然语言语义搜索（"给我所有关于 OpenAI 的文章"）
- 对付费墙内容使用浏览器自动化通过已登录 Chrome 会话提取

### 用例4：商业顾问 Council

- 8个专家 Agent 并行运行：财务/营销/增长/内容等
- 数据源：YouTube Analytics、Instagram、Twitter、邮件、会议转录、Slack
- 每晚运行，各专家独立分析 → 合并器去重 → 按优先级排序 → Telegram 摘要推送
- 可追问任何推荐获取详情

### 用例5：安全 Council

- 每晚 3:30 AM 运行，避免与其他夜间任务冲突
- 多角色审查：攻击、防御、数据隐私、运维现实性
- 审查对象：完整代码库、commit 历史、日志、错误日志、数据
- 产出编号报告 → Telegram 推送 → 可追问深挖 → 可直接说"修"
- 关键发现立即告警

### 用例6：社交媒体追踪

- YouTube/Instagram/X/TikTok 每日快照存入 SQL
- YouTube 追踪：每个视频的观看量、观看时长、互动率
- 数据喂入商业 Council 和每日简报

### 用例7：视频选题管线

- Slack 线程中回复 "this is a video idea" 触发
- 流程：读取线程上下文 → 搜索 X 趋势 → 查询知识库去重 → 深度研究 → 生成大纲/包装建议/钩子 → 创建 Asana 卡片
- 评估选题是否值得做（已做过的跳过）

### 用例8：每日简报

- 夜间扫描：CRM、邮件、次日日历、社交数据、行动项
- 早间 Telegram 推送：视频表现、会议上下文、待办事项

### 用例9：Cron 调度

- 夜间：文档同步、CRM 扫描、配置审查、安全审查、日志摄入、视频刷新、晨间简报
- 日间：Fathom 每5分钟、邮件每30分钟、行动项每日3次
- 每周：记忆合成（内置）、财报提醒、每小时 Git + 数据库备份
- 中央 Cron 日志库记录所有成功/失败

### 用例10：安全加固

- **确定性层**：正则代码检测 prompt injection 模式，清洗后再摄入
- **非确定性层**：LLM 扫描可疑内容
- **权限隔离**：不给 OpenClaw 对邮件/日历的写权限
- **秘密保护**：出站自动脱敏、不存储 secrets 到日志、pre-commit hook 拦截
- **行为约束**：要求审批后才发邮件/推文、忽略 "ignore previous instructions" 类指令

### 用例11：数据库备份

- 自动发现所有 SQLite 数据库 → 加密打包 → 上传 Google Drive → 保留最近7份
- 每小时 Git autosync：检测变更 → 提交 → 推送 → 失败告警
- pre-commit hook 防止意外提交敏感数据（如浏览器 profile）
- 完整恢复脚本，换机器可快速重建

### 用例12-13：图片/视频生成

- 集成 Runway（视频）和 Nano Banana Pro（图片）MCP
- Telegram 直接请求 → 生成 → 发送 → 删除本地文件
- 用途：缩略图、社交媒体素材、视觉资产

### 用例14：自我更新

- 每晚9PM 检查 OpenClaw 新版本
- Telegram 推送更新日志 → 用户说"更新"→ 自动更新 + 重启网关

### 用例15：API 调用追踪

- 追踪所有 LLM 调用：哪个模型、多少 token、哪个提供商
- 用于成本监控和优化

### 用例16：模型特定提示指南

- 下载各前沿实验室的提示最佳实践（如 Opus 4.6 提示指南）
- 本地存储，OpenClaw 更新任何 prompt 或 markdown 文件时自动参考
- 示例：Opus 4.6 不喜欢全大写 CRITICAL（会过度触发），GPT 则相反

### 用例17：开发工作流

- 复杂任务自动派生子 Agent（后台执行，主对话保持响应）
- 简单改动自己做，中等及以上委派给 Cursor Agent CI
- 健康监测心跳机制
- 注：OpenClaw 本身也能用 Claude Code 做所有编码，Cursor 只是个人偏好

### 用例18：饮食追踪

- 拍照记录食物 + 每日3次报告胃部状况
- 识别模式：发现洋葱是胃部不适的触发因素
- 每周分析 + 建议

### 其他用例

- 紧急邮件通知（每30分钟扫描，仅推送真正紧急事项）
- 团队知识分享（入库内容自动转发 Slack）
- 跨系统主动建议（CRM + 知识库 + 赞助商关联）

## 我的评注

- **赞同**：用例之间的复利效应是这个视频最有价值的洞察。单独一个 CRM 或知识库只是工具，但当它们相互喂入——CRM 联系人出现在视频选题建议中，知识库文章触发商业 Council 的分析——系统从"做任务"变成"产生洞察"。这与 [[复利工程]] 的核心论点完全一致
- **赞同**：行动项管线的自学习机制（被拒绝的项触发 prompt 更新）是少数被明确展示的 Agent 自我进化实例，比 [[BV1paf9BTEBk-OpenClaw现场演示如何使用]] 中笼统的"它会自己变好"具体得多
- **质疑**：视频对安全的处理依然停留在"尽力而为"层面。确定性代码清洗只能捕获已知模式的 prompt injection，对新型攻击完全无效。隔离权限是好的，但所有数据最终汇聚到同一台 MacBook 的 SQLite 数据库——单点故障风险巨大。与 [[BV1NscRzUEia-OpenClaw实战养虾指南]] 的三层纵深防御相比，这个视频的安全措施明显更薄
- **质疑**：21个用例的展示偏"效果"轻"代价"。每个管线搭建需要多少迭代？失败率多少？维护成本如何？视频把这些都隐去了，给人"30分钟搞定"的错觉。养虾指南视频更诚实——45亿 token 用量、持续修剪 prompt 文件、频繁修复日志——这才是真实的运维图景
- **关联**：与 [[上下文工程]] 的深层联系——模型特定提示指南本质上是上下文工程在模型可移植性维度的延伸：同一意图，不同模型需要不同的上下文表达方式
