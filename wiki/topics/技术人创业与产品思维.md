# 技术人创业与产品思维

## 核心主张
技术人做产品最大的障碍不是技术能力不足，而是**认知陷阱**——把"代码优雅"等同于"商业价值"，在自己脑子里的假环境优化，而非真实环境中的探索。这个陷阱不只是产品领域的问题，在 AI 训练中同样存在：环境偏见让模型记忆对手而非学习策略，就像技术人记忆"完美产品该长什么样"而非学习"用户实际需要什么"。

## 综合分析

### 认知陷阱：在自己的脑子里优化

来自 [[BV1SqDcBCEwW-关于一人公司也就是OPC的业务思考]] 的核心论据：技术人普遍存在"造完美轮子"的执念——代码优雅、架构清晰、测试覆盖面面俱到。这是学校教育训练的标准，但在商业世界里，标准只有一个：能运行、能用。UP主觉得28个扣子工作流+飞书文档"拿不出手"，咬咬牙发出去，首月变现1.2万。过度准备的本质是害怕真实反馈的"怂"。

来自 [[BV1D9ojBzEAd-将小模型训练成特定领域大师]] 的跨领域映射：RLVR 训练中的"环境偏见"问题和产品思维中的认知陷阱是同构的。Deepset 工程师发现 minimax 算法在多个最优走法中总是选第一个，导致模型实际上在记忆特定对手的走法，而非学习通用策略——模型以为自己在"学习下棋"，其实在"记忆一个特定对手"。技术人以为自己在"做产品"，其实在自己脑子里记忆"完美产品该长什么样"——两者都是在假环境中的优化，而非真实环境中的探索。

### 做减法：跨领域的元模式

**MVP 思维**（来自 [[BV1SqDcBCEwW-关于一人公司也就是OPC的业务思考]]）：不要等产品完美再上线。可以是一份文档、一个咨询、一个半成品demo，只要能解决问题、用户接受、收到钱，就是 MVP。用户不勤奋，只想用不想学——产品必须操作简单、使用成本低。

**克制式设计**（来自 [[BV1Y4oLBuEu6-吃透Claude-Code核心源码]]）：Claude Code 不断收缩工具暴露量（52→~20个），激发模型自身能力而非堆工具。这与 MVP 的"砍功能"是同一逻辑：约束产生聚焦，聚焦产生突破。

**RLVR 环境设计**（来自 [[BV1D9ojBzEAd-将小模型训练成特定领域大师]]）：可控的对手技能（不是最强也不是最弱）、确定性种子（减少噪声）、分层采样（平衡对手多样性）——每一个设计决策都是在"做减法"：去掉不必要的复杂性，让学习信号更清晰。

**元模式**：三者都是"减少预设、增加反馈"——MVP 减少产品预设增加市场反馈，Claude Code 减少工具预设增加模型自主决策，RLVR 减少环境噪声增加学习信号质量。详见 [[MVP思维]] 的深层联系部分。

### "营销 > 产品"需要批判性理解

来自 [[BV1SqDcBCEwW-关于一人公司也就是OPC的业务思考]] 的观点：在目前环境下，营销往往大于产品本身。50页完美商业计划书 vs 丑陋但已有用户的demo——投后者。

但这个说法需要补充：产品本身可以成为营销载体。Stripe 的 API 设计优雅到开发者自发传播，Notion 的产品体验本身就是增长飞轮。"营销 > 产品"在0→1阶段成立（先验证方向），但在1→10阶段可能翻转（产品力成为护城河）。

来自 [[BV1f3veB1EE5-应用程序设计十倍提升]] 的关键补充：**在 Vibe Coding 时代，设计就是营销**。Chris 的热量追踪应用 A 在推文发布 20 小时内获得 800 waitlist 注册，不是因为功能更好（市面上有做 $300万/月的竞品），而是因为微交互和动画细节让概念视频"看起来不一样"。同概念无动画版本仅获 7 个点赞——这是"产品力即营销力"的极端实证。更深层的是，Chris 的应用本身就是一个验证循环：先发概念视频（MVP），看用户反应，再决定是否真正构建。设计不是产品做完后才加的装饰，而是**验证产品假设的武器**。

### 获客能力：比产品本身更稀缺的技能

来自 [[BV1ptrMBhE2X-百万美元SaaS蓝图]] 的核心论据：Rob Hoffman 用六个经过实战验证的获客剧本证明，在 Vibe Coding 时代，**人人都能做出产品，但没人知道怎么获客**。这六个剧本覆盖了从"先有产品再获客"（等待名单策略、高客单价广告策略）到"先有需求再做产品"（乘风策略、语言套利策略）的光谱，以及"重新定义获客渠道"的新范式（AI 搜索策略、信号搜索策略）。

与前述论点的综合：MVP 思维解决"做什么"，设计曝光解决"怎么做"，而获客能力解决"怎么让人知道"。三者缺一——没有 MVP 思维，你做了一堆没人要的东西；没有设计能力，你做出来了但无法在信息流中脱颖而出；没有获客能力，你做出来了也很好看，但没人看见。Rob 的六个剧本中最值得注意的是**乘风策略**和**AI 搜索策略**——前者把"找需求"从脑暴变成了对公共对话的实时观测（和 MVP 的"减少预设、增加反馈"一脉相承），后者揭示了 AI 搜索推荐带来的转化率数量级提升（和 [[AI评估体系]] 的"AI 做隐含评估"逻辑同构）。

但需要补充的是：获客能力的前提是**方向正确**。六个剧本都是获客技巧，没有涉及需求验证——如果产品本身没人需要，获客效率越高浪费越大。"营销 > 产品"在 0→1 阶段成立，但前提是方向大致正确。

### AI 原生商业：不需要 VC 的可持续增长

来自 [[BV1Ru4QzHEZR-ChatPRD产品经理与AI]] 的核心论据：Claire Vo 用 Chat PRD 证明了 AI 原生产品可以遵循一条完全不同的增长路径——构建成本极低（一个人感恩节假期搭出产品）、现金流为正（6 个月千用户付费）、不依赖风险投资。她的论断直指核心：**千万美元年收入足以改变创始人生活，但这不是 VC 想要的回报曲线**。拿了 VC 的钱就要走 VC 的路，而这条路意味着你必须追求十亿美元级退出——这对大多数工具类 SaaS 来说既不现实也不必要。

与前述论点的综合：MVP 思维解决了"做什么"，获客能力解决了"怎么让人知道"，而 AI 原生商业模式解决了"怎么可持续地活下去"。三者构成了一个完整闭环：用最低成本验证（MVP）→ 用最高效方式获客（六个剧本）→ 用最轻量模式运营（不融资、小团队、现金流驱动）。Claire 的每周发版承诺既是产品策略（持续交付），也是获客策略（社区活跃度），还是商业模式验证（证明构建成本低到一个人能持续产出）。参见 [[AI原生商业模式]]。

但需要补充的质疑：Claire 的案例有一个被忽略的前提——她本身是 CPO，有 20 年产品经验和大量产品内容粉丝。这不影响"构建成本低"的结论，但直接影响"获客容易"的判断。对于没有分发渠道的人，AI 降低了构建门槛，但没有降低分发门槛。

### 激进实用主义：去情绪化决策与安静做事

来自 [[BV1D1w3zMEur-Intuition CEO：AI革命不是软件 是农场、矿山和卡车]] 的核心论据：Qasar Younis 提出"激进实用主义"——所有价值观从"什么实际有效"出发，而非从哲学推导。两个关键实践：一是去情绪化决策——"假装没人在乎感受，你会怎么选？那就是正确答案"，然后回来处理人的感受；二是安静做事——Applied Intuition 近 10 年、1000+ 工程师、从未花过融资款，和硅谷 build in public 文化反着来。

与前述论点的综合：MVP 思维是"做减法"在产品层的体现，激进实用主义是"做减法"在决策层的体现——减少情绪预设增加决策质量，减少公开活动增加产品专注。两者底层逻辑一致：**去掉噪声，让信号通过**。但需要警惕：Qasar 的"安静"能成立是因为他已有 YC COO 的网络和顶级 VC 背书。对于无网络的创始人，build in public（和 [[乘风策略]] 一致）可能是建立网络最高效的方式。实用主义不应该教条化为"永远安静"，而应该是"在当前约束下选 ROI 最高的路径"。

另一个重要贡献是"最佳想法胜出"的组织实践——公司失败往往不是缺人才，而是 momentum 淹没了最佳想法。Google 拥有最好工程师和最多现金却打不过 Facebook，因为 Google 不是 Facebook。**大猩猩学飞的方式不是做大猩猩。**这和 MVP 思维的"不要在假环境优化"同构——Google 在自己熟悉的搜索范式里优化社交产品，就像技术人在自己脑子里优化完美产品。

### 从"神经"出发：选品的方法论化

来自 [[BV1TRvYBtEfD-10款月入5万美元的未知应用]] 的核心论据：Greg 提出了 IUSR 神经框架——成功的利基市场需要同时具备身份（Identity）、紧迫性（Urgency）、利益攸关（Stakes）和重复频率（Repetition）。核心问题不是"技术能做什么"，而是"谁有一个愿意付费消除的重复性痛苦"。10款月入$50K+的应用验证了这个框架：黑胶唱片收藏家（身份+利益+重复）、教堂会众（仪式重复+高意图内容）、室内设计决策者（消除不确定性的紧迫性）。

与前述论点的综合：MVP 思维解决了"做什么的判断标准"，获客能力解决了"怎么让人知道"，而 IUSR 神经框架解决了**"怎么找到值得做的事"**——这是选品层面最上游的问题。三个框架构成完整链路：用 IUSR 找到有"神经"的利基→用 MVP 验证最小可行产品→用获客剧本放大触达。特别值得注意的是"高意图输入"原则（参见 [[高意图输入]]）——当用户愿意拍照、扫描、定位时，他已经自我筛选为高价值用户，这和 [[乘风策略]] 中"搭已经爆发的注意力便车"逻辑一致：不要创造意图，要找到已有意图的载体。

但需要补充的质疑：Greg 的框架隐含假设是"利基市场足够大"——宗教应用月入$60K的前提是全球有十亿+基督徒。对于一个只有几千人的利基群体，即使 IUSR 全满足，收入天花板也很低。选品不只是找对神经，还要判断神经的规模。

另一个重要贡献是"一个任务做到极致"的产品设计原则——下一个$50K MRR 应用 = 1个任务 × 1个受众 × 1个重复需求。这和 [[MVP思维]] 的"做减法"一致，但更进一步：MVP 是验证阶段的减法，而 Greg 主张**永久最小产品**——功能足够少到不需要文档，价值足够高到用户愿意付费。参见 [[AI微应用]]。

## 仍然开放的分歧

1. **微交互的 ROI 在哪个拐点递减？** Chris 的案例证明从 0→10 个微交互的回报极高，但从 90→100 个呢？在"够用"和"精致"之间，独立开发者的时间预算应该分配在哪个区间？
2. **产品什么时候从"够用就行"升级到"必须打磨"？** MVP 验证后的迭代路径是什么？从"丑陋demo"到"可持续产品"的转折点在哪？
3. **一人公司的规模化瓶颈** — 当"不勤奋的用户"需要更多服务时，超出一人的交付能力，如何破局？
4. **精准流量 vs 爆款** — UP主首月400粉丝变现1.2万证明精准流量有效，但这是否可持续？规模化的路径是什么？
5. **获客剧本的可复制性边界** — 视频中案例创始人大多有受众基础或多次创业经验，"任何人都能做"的说法忽略了积累的复利效应。无脸账号从零起步可行，但内容能力的培养周期有多长？
6. **AI 原生商业的规模化瓶颈** — 从千用户到十万用户，客服、合规、数据安全、SLA 的运营成本不会因为 AI 编码变快而降低。"构建成本低"的结论在规模化阶段是否仍然成立？
7. **微应用的护城河在哪里？** — API 能力同质化后，Logo Maker 月入$200K 的局面能维持多久？从单功能产品向功能组合扩展的路径和时机？
8. **IUSR 神经框架的利基规模盲区** — 框架验证了"什么样的利基能做出产品"，但没有回答"这个利基的天花板有多高"。小而美的利基和小而穷的利基如何区分？

## 我的立场

技术人认知陷阱的根源是**缺乏真实环境反馈的训练**——学校只训练"在给定需求下写出好代码"，不训练"发现什么需求值得写"。这和 SFT 只训练"模仿示例"不训练"探索更优策略"是同一个问题。解法也是一样的：从 SFT 转向 RLVR——从"在自己脑子里优化"转向"放到真实环境中试错"。
