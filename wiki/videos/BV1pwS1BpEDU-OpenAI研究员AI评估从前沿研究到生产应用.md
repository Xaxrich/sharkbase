# OpenAI研究员：AI评估，从前沿研究到生产应用

## 一句话摘要
OpenAI 前沿评估团队公开 GDPVal——用真实经济任务替代学术基准测试衡量模型能力，同时发布评估产品工具链（可视化构建器、trace 评分、自动 prompt 优化），让开发者能以同等严谨度评估自己的应用。

## 核心观点
- 学术基准测试（SAT、LSAT、AIME）已饱和——模型满分但不会做真实工作，需要转向测量"经济价值任务"的实际完成度
- GDPVal 覆盖美国 GDP 贡献前九大行业、1000+ 真实工作任务，用配对专家盲评衡量模型胜率，GPT-4 仅 20%，当前模型接近 40%
- 评估是前瞻性指标而非滞后指标——使用数据（usage data）反映的是过去，评估反映的是模型能力趋势
- GDPVal 有明确局限：只测量"明确定义输入输出的任务"，不涉及优先级判断、反馈迭代等真实工作的核心部分
- 开发者侧评估工具链已产品化：数据集构建器、trace 评分、自动 prompt 优化、第三方模型支持（OpenRouter/Bring Your Own Key）

## 详细笔记

### 第一部分：前沿模型评估——从考试到工作（Tail）

#### 为什么需要新的评估方式
- 训练 runs 极其昂贵（算力+研究者时间），需要信号来衡量进展、判断是否需要干预
- 传统学术基准（SAT、LSAT、AIME）的问题：模型已接近 100%，但无法做真实工作
- 类比：全 A 学生不等于好员工——通过考试和完成真实工作是两回事

#### GDPVal 的设计
- **命名逻辑**：覆盖与 GDP（国内生产总值）相关的任务，衡量模型在经济价值真实任务上的表现
- **任务来源**：由平均 14 年经验的领域专家制作
- **覆盖范围**：
  - 美国 GDP 贡献前九大行业（每个行业贡献 >5% GDP）
  - 每个行业前五大知识型职业（按工资贡献排序）
  - 每个职业覆盖其主要工作任务（基于政府追踪数据）
  - 总计 1000+ 真实任务，覆盖房地产、CAD 设计、零售等
- **任务特征**：长时程（数天到数周）、多模态（计算机操作、图像、工具使用）

#### 评分方法：配对专家盲评
- 模型输出 vs 人类专家交付物，盲评打分
- 滚动计算胜率（win rate）：模型输出被偏好的百分比
- 结果：GPT-4 胜率 <20%，18 个月后 GPT-5 接近 40%，Claude 在某些任务已接近持平

#### 为什么构建 GDPVal
1. **经济影响评估**：经济学家当前用使用数据，这是滞后指标——飞机从发明到广泛使用花了数十年，AI 也一样
2. **内部导航星**：研究团队用它追踪模型进展、指导训练方向

#### 局限性
- 不等于"AI 取代所有工作"——只测量明确定义的任务
- 真实工作还包括：确定做什么、优先级排序、接受反馈迭代
- 未来版本将纳入这些维度

### 第二部分：开发者评估工具链（Henry）

#### 为什么开发者需要评估
- LLM 非确定性、模型不断更新、边界情况无穷
- Agent 系统中错误率逐层累积
- 受监管领域（金融、法律、医疗）对错误零容忍

#### 新功能
1. **可视化 Eval 构建器**：拖拽式数据集构建 + 人工标注在同一界面
2. **Trace 评分**：对 Agent 运行轨迹批量运行评分器，定位失败节点
3. **自动 Prompt 优化**：基于标注数据 + 评分结果 + 原始 prompt 自动重写
4. **第三方模型支持**：通过 OpenRouter 和 Bring Your Own Key 评估非 OpenAI 模型
5. **企业级就绪**：零数据留存、企业密钥管理

#### Demo：Carlysle 投资基金 Agent
- 用 Agent Kit 构建多 Agent 分析系统（基本面分析、批评、最终报告）
- **单节点评估**：选一个 Agent → 创建 eval → 上传样本数据 → 人工标注 + LLM Judge → 自动优化 prompt
- **端到端评估**：对完整 trace 附加评分规则（如"引用源必须是一手来源"、"输出必须有明确买入/卖出/持有评级"）→ 批量评分 → 定位问题 trace

#### 评估工具选择的三个维度
1. **集成度**：构建→评估→优化→部署的一体化工具链
2. **自动化**：prompt 优化已上线；数据集生成、评分器对齐即将推出
3. **易用性**：降低领域专家参与门槛，在一个界面捕获偏好数据

#### 实践经验三条原则
1. **从简单开始，开发初期就建 eval**——不要等到最后，先定义简单集合，随应用演进而迭代
2. **用真实用户数据**——不要编造假设性例子，采样真实历史用户输入
3. **用领域专家标注**——把时间花在确保偏好数据被评分器和 prompt 正确捕获，让自动化工具处理重复性工作

## 我的评注

- **赞同**：GDPVal 的设计哲学——用真实经济任务替代学术基准——是正确的方向。SAT 满分不等于会干活，这个类比精准且有力。配对盲评的评分方法也比传统的自动评分更诚实。
- **赞同**：三条实践原则（尽早建 eval、用真实数据、专家标注）与之前知识库中 AI 评估体系的核心判断一致——人工标注是一切的基础，自动化工具是放大器不是替代品。
- **质疑**：GDPVal 的"胜率 40%"数据需要谨慎解读。配对盲评只衡量"输出是否可接受"，不衡量"任务是否真的完成"——模型可能产出了一个看起来不错的幻灯片，但其中的数据准确性、专业判断深度并未被严格验证。演讲者自己承认只测"明确定义输入输出的任务"，这恰恰是真实工作最不典型的部分。
- **质疑**：自动 prompt 优化功能被过度包装。它的本质是"用更多 LLM 调用来优化 LLM 调用"——如果评分器本身对齐不准，优化只会把 prompt 推向错误方向的更优解。没有提到对齐验证机制。
- **关联**：GDPVal 与 [[AI评估体系]] 中四种评估类型的关系——GDPVal 属于"人工评估"（专家盲评）的高阶形式，而 Henry 的产品工具链中的 LLM Judge 属于"LLM-as-Judge"。两者的一致性在于：人工评估是锚点，LLM-as-Judge 是规模化手段。这与 [[BV1gXqLBXE87-AI评估实战50分钟完整入门课程]] 的核心论点完全一致。

## 待深入问题
- GDPVal 的配对盲评是否只评估"表面质量"而忽略了专业深度？一个护士的幻灯片看起来不错，但医学准确性如何？
- 当模型胜率接近 50% 时，评估的区分度会急剧下降——如何设计更精细的评估来区分"可接受"和"优秀"？
- 自动 prompt 优化的对齐验证：如何确保优化方向与人类偏好一致，而不是走向评分器偏差的更优解？
- Agent 系统的 eval 如何处理"正确输出但错误路径"的情况——trace 评分是否足够？
