# EvoMap策略基因：从视频到可复用 Agent 工程方法

## 一句话导读
EvoMap 的关键判断是：经验复用的难点不是存更多经验，而是把经验编码成能在测试时直接约束模型行为的高密度控制信号。

## 适合谁看
- 正在做 Agent、工具调用、Skill 库或长期记忆系统的开发者。
- 需要把论文方法转成工程决策和评估标准的产品/研究同学。
- 想理解 Agent “自进化”到底发生在模型、外壳、技能还是数据层的人。

## 读完你会获得什么
- 能解释 `EvoMap策略基因` 解决的核心 Agent 工程问题。
- 能区分它和同系列其他 Agent 进化路线的不同位置。
- 能把论文思路转译为自己的 Agent / Skill / Harness 系统设计检查项。
- 能识别这一路线的适用边界和潜在风险。

## 核心框架
- 面向人阅读的完整 skill 文档不一定适合作为模型的即时控制上下文。
- strategy gene 是短小的作战卡片，包含任务匹配信号、摘要、策略、失败警告和验证约束。
- 许多科学代码失败来自单位、参数语义和输出转换等细节，gene 用极短文本提醒模型避坑。
- 实验把任务输入和控制表示分开，变化只来自经验表示本身。
- 核心贡献是把经验表示从“文档化”推进到“控制化”。

## 01 Skill 文档的问题

- 完整文档适合教学、审查和维护，但进入上下文时会稀释真正影响行为的信号。
- 模型测试时最需要的是能立刻改变决策的边界条件和错误警告。

## 02 Strategy Gene 的形态

- 它不是普通摘要，而是按任务匹配、策略动作、失败风险组织的控制对象。
- 典型内容包括单位转换、函数参数含义、验证步骤和不要做什么。

## 03 对 Agent 经验库的启发

- 同一经验可以保留两个版本：给人看的 skill 文档，以及给模型执行时看的 gene。
- 经验库不应只追求完整性，还要评估进入上下文后的控制强度。

## 落地检查清单
- [ ] 这个方法优化的是模型内部能力、外部 harness、技能库，还是训练数据？
- [ ] 它依赖哪些可观测证据：轨迹、日志、分数、用户反馈、测试结果？
- [ ] 它的更新是否有验证、回滚或淘汰机制？
- [ ] 它是否会引入上下文成本、技能污染、过拟合或安全审计风险？
- [ ] 如果迁移到自己的项目，最小可试验版本是什么？

## 常见误区
- 不要把“保存更多历史”直接等同于“Agent 学会了经验”。经验必须变成可检索、可验证、可控制的表示。
- 不要只看单次成功案例。Agent 进化需要跨样本证据、失败归因和回归验证。
- 不要忽略运行成本。技能库、harness 日志、动态数据和测试沙箱都会引入额外 token 或执行成本。
- 不要把自动更新直接上线。共享技能和 harness 改动尤其需要灰度、回滚和审计。
