# 代码组织与可维护性

## 定义
AI 生成代码时的模块化程度——是拆分为独立文件/目录，还是塞进单个大文件。这不仅是审美偏好，而是直接影响后续 Agent 审查和 bug 修复能力的工程决策。

## 为什么重要
模块化代码让后续 Agent review 能定位并修复 bug；单一大文件中同样的 bug 会被遗漏。这不是理论推断，而是实测结果——同一 prompt 下，模块化产出经过 agent review 后 bug 被修复，大文件产出中相同 bug 仍然存在。当 AI 编程从"一次生成"走向"持续迭代"，代码组织成为比生成质量更关键的变量。

## 我的判断
当前 Opus 在代码模块化上仍领先，5.4 比 5.3 有进步但仍偏大文件。这个问题会被低估，因为"能跑"的代码看起来和"能维护"的代码在第一次 review 时区别不大，区别在第二、三次迭代后才暴露。代码组织不是模型能力的边缘问题，是决定 AI 生成代码能否长期存活的核心问题。
