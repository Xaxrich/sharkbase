# 智能体分工

## 定义
不追求一个全能 Agent，而是让不同 Agent 各司其职——像招聘专家一样，每个 Agent 解决它最擅长的问题。Claude Code 做研究和通用编码，Friday 做 UI 实现，Charlie 做代码审查。

## 为什么重要
当前没有一个 Agent 在所有方面都是最好的。Cursor 在代码编辑体验上强，Claude Code 在灵活性和研究能力上强，Friday 在 UI 实现上有独到品味。试图用一个工具做所有事，要么在弱项上浪费时间，要么在切换上下文时丢失信息。分工模式让每个任务用最合适的工具，同时通过 GitHub PR 等标准流程串联 Agent 间的协作。

## 我的判断
- **赞同**：分工模式比"一个 Agent 统治所有"更务实。不同 Agent 的能力差异是客观存在的，承认并利用这种差异比等待"终极 Agent"更高效。
- **质疑**：Agent 间上下文传递的损耗问题被低估了。当 Claude Code 做完研究生成 Issue，Friday 实现，Charlie 审查——每个 Agent 看到的上下文都是局部的。人类工程师在同一代码库中长期工作积累的隐性知识，Agent 间无法直接传递。
- **补充**：分工模式的成本是认知负载——你需要记住每个 Agent 的强项和弱项，以及何时切换。对新手来说，"就用 Claude Code 做一切"可能比"在五个 Agent 间切换"更高效。

## 深层联系
