# 提示注入

## 定义

通过在用户数据（邮件、网页、文档等）中嵌入恶意指令，欺骗 AI Agent 执行攻击者想要的操作而非用户想要的操作。本质上是利用 LLM 无法区分"指令"和"数据"的缺陷。

## 为什么重要

当 Agent 只是一个聊天机器人时，提示注入顶多让你得到一个搞笑回答。但当 Agent 拥有执行能力——读写文件、发送邮件、操作账户——提示注入就从恶作剧变成安全灾难。Agent 越自主、权限越大，提示注入的杀伤力越大。这是当前 AI Agent 从"玩具"走向"生产工具"的最大安全障碍。

## 我的判断

"2-3 个月内社区会解决安全"是过度乐观。提示注入是 LLM 架构层面的根本问题——模型用同一个表示空间处理指令和数据，没有结构化的隔离机制。当前的防护（权限隔离、独立账户、最小权限）都是权宜之计，不是根本方案。真正的解决可能需要模型架构层面的改变（如指令通道与数据通道分离），这不会在几个月内发生。

## 深层联系

- [[主动式Agent]] — 主动式 Agent 与提示注入是一体两面：Agent 越主动（自己读邮件、浏览网页），攻击面越大。权限隔离是当前唯一的务实折中
- [[上下文工程]] — 提示注入是上下文工程的对立面：前者是让不该进入上下文的信息污染决策，后者是精准控制什么进入上下文
- [[驾驭工程]] — 权限隔离、最小授权、逐步信任——这些安全实践本质上是驾驭工程在安全维度的应用
