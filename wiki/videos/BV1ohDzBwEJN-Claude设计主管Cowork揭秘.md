# Claude设计主管：Cowork揭秘，40分钟教程

## 一句话摘要

Anthropic 设计主管 Jenny 详解如何用 Cowork 重塑产品设计流程，以及 Cowork 从一年原型探索到10天冲刺出货的真实故事。

## 核心观点

- **Co 已成为设计师的主要工具**：除了最终的生产代码打磨，Jenny 几乎所有工作都在 Co 里完成——从用户洞察到产品方案到团队演示
- **"10天做出来的"是误读**：Cowork 方向酝酿了一年，经历多次原型迭代和技术实验失败，10天只是最终冲刺出货的时间窗口
- **内部狗粮是最强信号源**：内部用户比外部用户更诚实地指出交互问题，外部用户更多反馈"能不能满足我的流程"
- **UI 迭代方向是从结构化到自由化**：早期的向导式、工作流式 UI 全部被剥掉，最终回归简洁的聊天框 + 任务列表
- **设计师的角色正在从"产出者"变成"策展者"**：AI 生成选项，人负责判断和微调；但判断力本身需要大量反馈喂养

## 详细笔记

### Jenny 的日常工作流

- 不存在"典型的一天"，但核心模式是：同时咨询 5+ 个项目，与工程师和 PM 非正式 jam
- 大量时间花在看内部原型、使用功能、形成观点，然后和工程师坐下来对齐方向
- 仍然会进 Figma 打磨细节，但比重在下降
- Figma 和详细 spec 仍然存在，但主要用于安全/合规评审，不再是设计过程的核心载体
- spec 从精美表格变成了几条 bullet point

### 用 Co 做产品设计的完整流程

1. **输入多源数据**：将 UXR 访谈文件夹、社交媒体反馈、用户评论都丢给 Co
2. **提取洞察**：Co 自动搜索网络、处理文件夹，生成结构化的7个洞察主题
3. **并行分支**：
   - 分支A：从洞察推导可建的产品功能，按优先级排序
   - 分支B：将洞察转为团队演示文稿
4. **生成线框图**：让 Co 为选定功能方向生成多个 wireframe 选项
5. **人介入微调**：选定方向后进 Figma 或 Claude Code 做真实设计系统下的高保真
6. **定时调度**：把整个流程设为每周一早10点自动执行，持续获取反馈→方案的闭环

关键心态：**永远让 AI 先出第一稿，自己只做反应式编辑**。Jenny 承认自己"变懒了"——不再从空白页开始。

### Co 与 Claude Code 的定位差异

- Co 适合非技术用户和日常知识工作，有 UI 界面，融入已有工作流
- Claude Code 适合深度代码工作，命令行界面
- 内部观察到：原来用 Claude Code 做非技术任务的人（销售用 CC 生成线索、脚本）已全部迁移到 Co
- Co 的采用面更广，因为它离用户已在用的 Chat 更近

### Cowork 的诞生故事

- **"10天做出来"是被断章取义的**：实际上这个方向从 Jenny 加入 Anthropic（约一年前）就在讨论
- 经历了多次原型实验：有些是产品团队做的，有些是 Labs 团队做的
- 多个 Agent harness 技术方案失败后才找到当前架构
- 关键转折：2024年底假期，大量非技术用户涌入 Claude Code，团队看到了 Agent harness 对非技术人的产品市场契合信号
- 决策：立刻出货，不等完美产品——抢窗口期比做完美更重要
- 10天冲刺出货是建立在一整年积累之上的

### UI 迭代的三个阶段

1. **工作流式 UI**：结构化的输入/输出区域，像工作流工具一样引导用户填表。问题：太死板，像在2025年还要填表
2. **向导式 UI**：按用途分类（分析/文档），每个用途有不同调节旋钮。问题：过度工程化，太多视觉元素竞争注意力
3. **极简聊天框 + 任务列表**：剥掉所有预设 UI，首页改为"你和 Claude 的共享待办清单"——审批、调度、查看状态全在一处

核心张力始终是：**多大程度规定用法 vs 多大程度让用户自由探索**。最终选择后者。

### Anthropic 的规划方式

- Co 团队做月度规划，不是季度或年度
- 整个团队待办清单最多12项，每项一个 DRI（直接负责人）
- 每周检查进度，但不做复杂的规划仪式
- 有季度/半年的方向对齐，但非常松散——更像是"大家往同一方向看"
- **愿景文档最多覆盖3-6个月**，不能更长——技术变化速度不允许
- 愿景最好是可视化的（原型优于静态 PPT），设计在凝聚分散团队方向上仍有巨大价值

### 对设计师的建议

- "如果你觉得脚下的地在晃，那是因为它确实在晃"——接受变化，质疑现有工作方式
- 工程师已经大规模适应了 AI 带来的角色转变，设计师应该以他们为榜样
- 被AI替代的不是设计师，而是设计师不愿意放手的那些低价值工作
- 现实：得到更多产能后，人倾向于做更多而不是更闲——因为雄心驱动

## 我的评注

- **赞同**："永远让 AI 出第一稿"的工作方式是当前最实用的 AI 协作策略。空白页问题被消除后，人的价值确实从"创造"转向"判断和策展"。Jenny 的周一自动化流程是一个很好的 AI 原生工作流范本。
- **赞同**：内部狗粮优于外部调研的观点很务实——内部用户既诚实又可追溯，反馈闭环速度完全不同。这和 Claude Code 成功的经验一致。
- **质疑**："10天出货"故事的叙述仍然有美化的成分。Jenny 说技术方案失败了多次才找到当前架构，但没有展开哪些方案失败、为什么失败——这些失败经验可能比成功故事更有学习价值。
- **质疑**：从结构化 UI 退回聊天框的决策，虽然短期内用户接受度更高，但长期来看可能会遇到"不知道 AI 能做什么"的发现性问题。Co 目前的极简 UI 对新用户可能反而不够引导。
- **关联**：这与 [[AI驱动的产品设计]] 和 [[MVP思维]] 深度相关。Jenny 描述的流程本质上是用 AI 压缩从反馈到方案的循环周期，和精益创业的 Build-Measure-Learn 异曲同工，只是 AI 把每个环节的时间都缩短了一个数量级。
