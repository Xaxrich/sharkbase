# 驾驭工程

## 定义
Harness Engineering（驾驭工程），指构建 AI Agent 时，除大语言模型本身之外的所有工程系统的总称——包括推理引擎、工具系统、记忆管理、安全约束、协作机制等。其语义经历了从测试领域到 AI 领域的多次演变。

## 核心要点
- **语义演变**：起源于测试领域的 test harness；被 Anthropic/OpenAI/LangChain 扩展到 AI 领域；OpenAI 定义三大支柱为 Engineering、Constraints、Garbage Collection；后泛化为 "Agent = Model + Harness"，Harness 成为模型以外一切的统称
- **同心圆架构**（以 Claude Code 为最佳实践）：
  - 核心：Model API（被驾驭的对象）
  - Query Engine（神经系统）：ReAct循环、Prompt工程、记忆管理、Token管理
  - Tool System（手脚）：基础工具、MCP工具、Skills系统
  - Agent Collaboration（团队协作）：SubAgent、ForkAgent、协调者模式、Team模式
  - Security（基础设施）：权限、沙箱、防注入、审计
- **设计哲学分歧**：Claude Code 走"克制式"路线——不断做减法收缩工程功能、激发模型能力；竞争对手走"做加法"路线——不断加功能扩能力
- **Garbage Collection 是关键**：对应 Auto Dream 等机制，决定项目空间能否持久运行而不劣化
