# ClawdBot：席卷硅谷! 最新AI工具

## 一句话摘要

Anthropic 设计师 Jenny 亲述如何用 Claude Co 和 Claude Code 重构产品设计流程，以及 Claude Co 从一年原型迭代到十天冲刺上线的真实故事。

## 核心观点

- Claude Co 和 Claude Code 的分工：Co 处理日常对话、洞察提炼、文档生成；Code 处理生产级代码和细节打磨
- 产品设计的关键转变：从写详细 spec 和精美 Figma 到用 AI 做"垃圾进、宝藏出"的快速提炼，再用人工判断做策展和决策
- Claude Co 的诞生并非"十天奇迹"——公司从一年前就在探索通用知识工作者的 AI 协作工具，经历了多个失败原型，十天冲刺只是最后的执行窗口
- 内部 dogfooding 是 Anthropic 产品成功的重要因素：内部用户给的是交互层面的深层反馈，外部用户更多给的是功能层面的使用反馈
- 设计师的角色正在从"产出者"转向"策展者"——AI 生成大量选项，人的价值在于判断和选择

## 详细笔记

### 日常工作流：从独立设计到多项目咨询

Jenny 的工作方式已大幅改变：

- 过去专注单个项目深度设计，现在同时在 5 个以上项目间做咨询
- 核心工作模式是和工程师、产品经理"jamming"——非正式地一起看原型、讨论行为、迭代
- Figma 和 spec 仍然存在，但大幅精简：spec 从详细表格变成几条 bullet points，主要用于安全审查和法律合规的交接
- 仍然需要进入设计工具做打磨和微迭代，这部分没有消失

### Claude Co vs Claude Code 的使用场景

| 场景 | 工具选择 |
|------|---------|
| 日常聊天/对话 | Claude Co |
| 洞察提炼（从大量数据中找重点） | Claude Co |
| 文档/演示生成 | Claude Co |
| 生产级代码 | Claude Code |
| 界面打磨和细节实现 | Claude Code |

非技术用户（如销售团队）更偏好 Co，因为 Co 有 UI、离现有工作流更近。命令行对非技术人员是额外摩擦。

### 用 Claude Co 做用户洞察的完整流程

1. **输入多源数据**：将 UXR 访谈转录稿文件夹挂载到 Co，同时让它搜索社交媒体和用户评价
2. **让 AI 提炼洞察**：Co 会派生子代理并行处理，从多源数据中提取主题
3. **并行产出**：一条线程生成功能建议，另一条线程把洞察做成团队演示文档
4. **从洞察到原型**：让 Co 生成线框图选项，选择方向后进入 Figma 或 Claude Code 做真实实现
5. **自动化循环**：将整个流程设为定时任务（如每周一上午 10 点自动执行），形成反馈→想法→原型的紧凑迭代环

### Claude Co 的诞生故事

"十天做出来"是误读：

- Anthropic 从 Jenny 入职（约一年前）就在思考通用知识工作者的 AI 协作工具
- 经历了多个原型和失败的技术实验（不同的 agent harness 方案）
- 关键转折：假期期间非技术用户大量尝试 Claude Code，发现了代码之外的使用场景（解析播客转录、复杂分析等），验证了 agent harness 对非技术人群的产品市场契合
- 团队决定加速发布：原本计划几周后上线，但判断"这是窗口期"，用 10 天冲刺完成发布
- 发布后通过真实用户信号快速迭代

### Claude Co 的 UI 迭代历程

经历了多次重大方向调整：

1. **工作流导向**：结构化输入/输出界面，类似自动化工具——失败原因：太死板、操作成本高，用户觉得"2025 年了为什么还要这样填表"
2. **引导式分类**：按"分析""文档"等分类引导用户，每种类型有不同参数调节——失败原因：过度设计，限制过多
3. **向导式创建**：点击创建文档，设定页数等参数，同时展示大量 UI 元素——失败原因：视觉元素互相竞争，信息过载
4. **最终方案——极简聊天+任务列表**：剥离大部分 UI，回到接近聊天的形式，但将首页改造成"你和 Claude 的共享待办列表"，活跃任务可审批/分诊

核心设计张力始终是：**多少引导 vs 多少自由**。最终选择偏向自由，让命令和技能成为高级用户的可选路径，而非必经之路。

### 规划方式

- 月度规划，用简单表格，最多 12 项，每项一个 DRI（直接负责人）
- 季度/半年度有方向性指引，但不强制执行
- 北极星愿景文档仍有价值，但有效期最多 3-6 个月——技术变化太快，长期愿景没有意义
- 设计在愿景阶段的独特价值：把多个团队的碎片想法策展成连贯的体验叙事

### 对设计师的建议

- 接受地面在脚下移动的事实
- 工程师已经经历了同样的适应过程，并且做得很好——以他们为榜样
- AI 消除了繁琐工作，但人不会因此获得更多空闲——反而会做更多高价值的事
- 人的核心价值从"产出"转向"判断和策展"

## 我的评注

- **赞同**：AI 产品的核心设计张力是"引导 vs 自由"，这个洞察非常准确。太多 AI 产品试图用过度结构化的 UI 来补偿模型的不确定性，结果适得其反。Anthropic 从"工作流导向"退回到"聊天+任务列表"的过程值得所有 AI 产品团队学习。
- **赞同**：内部 dogfooding 的区分很有洞见——内部用户给交互层面的深层反馈（"这个东西用起来不对"），外部用户给功能层面的反馈（"这个东西能不能做 X"）。两类反馈互补，缺一不可。
- **质疑**：Jenny 说"vision 有效期最多 3-6 个月"，但这可能只是 Anthropic 特殊情况。在技术快速变化期，短期 vision 合理；但对于成熟产品或非 AI 领域，长期 vision 仍然有方向性价值。不能把快速变化期的经验泛化为普遍规律。
- **质疑**：视频标题"ClawdBot 席卷硅谷"有明显的标题党嫌疑。实际内容是 Anthropic 内部设计师的工作流分享，"席卷"和"最新AI工具"的包装与内容并不匹配。Easonlee 的 AI 笔记频道在做信息搬运时，标题常有这种夸大。
- **关联**：与[[原型优先开发]]和[[微交互设计]]有深层联系——Jenny 描述的"jamming + 快速原型"工作流，本质上就是用 AI 加速了原型→反馈→迭代的循环，让"原型优先"从方法论变成了可执行的现实。
