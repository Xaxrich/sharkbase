# 任务即子Agent

## 定义
Claude Code 的内置任务系统本质上是子 Agent（SubAgent）的重命名和增强——每个任务拥有独立的上下文空间，可以传递信息，可以在不同 Claude Code 实例间共享。这个命名变化不是表面文章，而是概念上的关键转变：任务不再只是一个 TODO 条目，而是一个可以自主执行的 Agent 实例。

## 为什么重要
这个重命名揭示了一个深层架构变化：从"AI 维护一个任务清单"到"AI 为每个任务分配一个子 Agent"。前者是被动记录，后者是主动执行。跨会话持久化是最核心的能力突破——之前一个 Claude Code 会话中的想法无法传递给另一个会话，现在通过共享任务账本，多实例协作成为可能：一个实例做规划，一个做执行，一个做测试。这本质上是用任务系统替代了多 Agent 框架的编排层。

## 我的判断
"任务即子 Agent"的洞察很精准，但当前实现远未达到这个承诺。通过现场逆向工程发现：任务系统目前是会话级的而非全局的，依赖关系仅在同一会话内生效，缺少关键工作流状态（待审批、阻塞），没有项目/标签/优先级元数据。这是 v1 的典型特征——概念方向正确，但工程成熟度不足以支撑真正的多 Agent 协作。社区会用 hack 绕过限制（自定义属性前缀、手动读取其他会话的任务文件），等官方支持后再迁移。

## 深层联系

- [[智能体分工]] — 多实例协作（规划者+执行者+测试者）是智能体分工在单工具内的实现——不需要外部编排框架，通过共享任务账本实现
- [[异步Agent范式]] — 任务即子 Agent 让异步协作成为自然状态：你交办任务→子 Agent 执行→你回来审查结果，不需要同时在线
