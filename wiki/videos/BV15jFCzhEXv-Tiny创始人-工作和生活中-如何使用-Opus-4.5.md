# Tiny创始人：工作和生活中 如何使用 Opus 4.5

## 一句话摘要

Tiny创始人Andrew Wilkinson展示了他用Claude Code + Opus 4.5构建的一系列个人与工作自动化工具，并阐述了AI如何瓦解传统软件商业模式——护城河不再来自编程能力，而必须来自品牌、分发或硬件锁定。

## 核心观点

- Claude Code + Opus 4.5达到了"编程领域的AGI"——可以理解意图、执行长时间任务、不会陷入bug循环，同时保持人性化的交互质感
- 设计师是这个时代最大的受益群体：他们一直有审美和体验判断力，但缺执行力，现在可以端到端完成产品
- 传统软件护城河已崩塌——编程曾是稀缺且昂贵的技能，现在基本免费，软件公司的利润率将被压缩到1-2%
- AI个人自动化（邮件分诊、穿搭推荐、关系诊断）已经超过专业SaaS产品的实用性
- 真正的风险不是长期（20年后会好），而是过渡期——白领大规模失业可能引发类似大萧条的经济冲击

## 详细笔记

### 从Replit到Claude Code：Vibe Coding的质变

Andrew回顾了一年半前被Replit震撼但最终放弃的经历——那时候的vibe coding像"用Palm Treo看未来"。两周前开始用Claude Code + Opus 4.5，体验完全不同：

- 可以理解意图，执行长时间任务（"给它足够指令，能连续工作四小时"）
- 不会陷入bug循环，持续构建
- 同时兼具工程能力和人类共情/常识——其他模型越擅长编程，其他能力越差，Anthropic解决了这个问题
- 花费约$40/天，感觉像雇了30个员工24/7工作

### 个人生活自动化案例

#### Deep Personality — 关系诊断工具

- 起因：和女友想有一个基于两人关系的GPT
- 让AI列出治疗师评估伴侣所需的20种测试量表，用Claude Code构建成多选问卷
- 25分钟完成评估，输出45页AI分析报告：人格特质、依恋风格、暗黑三合一、理想职业等
- 伴侣匹配功能：输入两人评估结果，预测所有冲突模式——"我们读出来笑着，因为它完美预测了我们每一次吵架"
- 实际使用：吵架时问GPT，它指出表层争论下的深层触发点（"不是脏盘子的问题，是你小时候觉得不被看见"），瞬间化解冲突
- 整个网站从零到完成只用了两小时

#### 个人穿搭推荐系统

- 每天早上7点自动运行：查天气 → 访问Google Sheet中的衣柜清单 → 用Nano Banana生成4套穿搭渲染图（含Andrew本人的参考照片）→ 通过Twilio发短信
- 衣柜清单的建立方式：用Claude拍照识别所有衣物，转成CSV

#### 邮件分诊系统

- 每天200-300封邮件，之前需要全职助理
- 之前用Lindy做了路由自动化（减少50%负荷），但边缘情况处理不了
- 用Claude Code构建了自定义Web邮件客户端：按优先级排序、多选回复、QA模式逐题回答、自动生成草稿
- 一周内达到日常可用水平——对比Superhuman花了5年才做到基础功能

#### 孩子学校邮件自动化

- 学校邮件是全职工作：远足通知、签字链接、午餐安排
- 自动摄取所有学校邮件 → 发短信提醒（"Peter明天需要带午餐"）→ 自动加入家庭日历

### 工作中的AI应用

#### 会议反红旗检测（Lindy Agent）

- 录制所有会议，AI分析对话内容
- 高门槛触发：只在检测到操控策略（gaslighting、重新框架等）时才发短信警告
- 约每2-3个月触发一次
- 案例：承包商未交付反而指责Andrew粗鲁，AI一分钟内标记出操控策略，帮助Andrew从自责中走出来
- 关键原则：**不要在提示词中注入自己的观点**，否则AI会迎合你的偏见

#### "Good Boss"提示词（Super Whisper）

- 对着手机说出原始愤怒想法 → AI转化为成熟、得体的管理者反馈
- 情绪过滤层：防止冲动沟通破坏关系

#### AI审计的陷阱

- 曾让AI审计公司账目，提示词带了怀疑倾向 → AI报告"大规模欺诈"
- 实际情况：员工在星巴克买咖啡被标记为可疑礼品卡购买
- 教训：**提示词的措辞直接决定AI的分析倾向**

### Claude Code工作流技巧

- **Skills**：将常用原则（如文案写作风格参考Made to Stick）封装为skill，每次调用自动应用
- **跨设备同步**：cron job在所有Mac上运行，确保任何设备打开Claude Code都回到上次状态
- **MCP**：虽然还早、集成慢，但能看到"触手怪"式触达所有软件的未来
- **移动端**：Claude App的Code功能可以在手机上触发，拉取repo到虚拟机，创建PR
- **瓶颈**：产出代码的速度远超审查速度，闭环验证（尤其移动端）仍是开放问题

### Agent原生架构

Dan Shipper提出的概念：

- 每个软件本质上就是Claude Code + 一段指令
- UI中的按钮触发后台Agent执行任务
- **每个功能都是一个提示词** → 用户可以自定义功能，开发者观察用户自定义模式，将最佳提示词推入主线
- 软件比以往更灵活、更可定制

### 软件商业模式的崩塌

Andrew的核心论点：

- **披萨餐厅类比**：如果有人发明了1000美元的完美披萨机，消费者受益（好披萨无处不在），但经营者的利润率从10-15%压到1-2%
- 编程曾是软件的护城河（稀缺、难学、昂贵），现在基本免费
- 卡路里追踪App的教训：有人vibe code一个赚百万/月，三个月后所有人复制，利润归零
- 未来的护城河必须来自：品牌、分发渠道、硬件锁定
- **水力工厂类比**：不转电力的风车工厂会被淘汰，但转型的沉没成本很高

### 对未来的担忧

- 不担心20年后（会好），担心过渡期
- 白领大规模失业（律师、程序员、知识工作者）可能引发大萧条式冲击
- 失业者转向蓝领（如开HVAC公司），但大量涌入又压低蓝领利润率
- **投资算力是通往未来的收费站**：Andrew大量投资了 Iris（比特币矿业公司转型数据中心），股价从$0.10涨到$3

## 我的评注

- **赞同**：披萨餐厅类比精准——AI降低了软件生产的边际成本，但不消除差异化需求。消费者确实受益，经营者的超额利润确实会被压缩。这个框架比"软件已死"的极端论断更有解释力
- **赞同**：会议反红旗检测的设计原则（高门槛触发、不在提示词中注入观点）体现了AI辅助决策的正确姿势——AI做信号检测，人做最终判断
- **质疑**：Andrew说"两三年内不会有我们理解意义上的程序员"——这忽略了复杂系统的工程判断、架构决策、安全合规等非编码能力。vibe coding能产出一个邮件客户端，但能产出一个符合PCI-DSS的支付系统吗？
- **质疑**：Deep Personality的工具虽然震撼，但将临床心理学量表简化为多选问卷+AI分析，存在效度问题。量表的意义在于有受训治疗师的解读，纯AI输出可能产生误导性确信
- **关联**：与[[AI驱动的产品工作流]]和[[Agent原生架构]]高度相关——Andrew的实践正好是这两个概念的活例证。个人自动化工具的成功暗示了软件的未来形态：不是通用SaaS，而是每个人定制自己的工具
