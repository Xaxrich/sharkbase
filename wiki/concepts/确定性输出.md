# 确定性输出

## 定义
让 LLM 工作流中需要精确计算的部分由脚本代码执行，而非依赖模型的非确定性推理。将"理解意图"和"执行计算"分离——前者交给 LLM，后者交给代码。

## 为什么重要
LLM 做数据分析时，让模型"看一下数据然后给洞察"，结果每次不同且难以验证。视频中的营销数据分析场景：上传 CSV 后，如果只靠 LLM 自由解读，容易幻觉数字（如把收入算错）。但用 Skill 内嵌 Python 脚本计算总花费、各渠道转化率等指标，结果是确定性的——同样的数据永远出同样的数字。这不是否定 LLM 的价值，而是让 LLM 做擅长的事（理解需求、组织输出），让代码做擅长的事（精确计算）。

## 我的判断
这个分离原则是 AI 工程实践中最实用的洞察之一。但它容易被过度简化——"加脚本就行"。实际上，哪些步骤需要确定性、哪些可以容忍非确定性，这个判断本身需要领域知识。视频中对营销指标的脚本化是合理的，但"哪些指标值得看"和"趋势如何解读"仍然是 LLM 的非确定性输出，这个分层不应被忽视。
