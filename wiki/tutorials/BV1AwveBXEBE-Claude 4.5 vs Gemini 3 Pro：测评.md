## 01 背景：为什么这个问题现在值得讨论

两件事同时发生了。

第一，AI编码模型的能力跃迁。Claude Opus 4.5、Gemini 3 Pro 等模型可以在极少提示下生成完整的落地页和可点击原型。一年前，非技术创始人想建一个产品原型，要么找人外包，要么花几周学代码。现在，一段描述就够了。

第二，产出质量的分化。同样用这些模型，有人一次提示就得到专业级产出，有人反复调了十几轮还是"AI味"十足。差异不在模型，在于使用方式。

具体表现：

- **设计同质化严重。** AI生成的页面普遍使用紫色渐变、emoji、同样的插画风格。不费力的"一键生成"正在制造一种新的视觉疲劳。
- **文案是更大的短板。** 页面看起来还行，但文字空泛、CTA模糊、没有痛点刺激。转化率低，归因于"vibe coding不行"，其实问题出在文案。
- **模型对比的焦点偏了。** 大量讨论集中在"哪个模型更强"，但真正决定输出质量的是前置工作——你是否定义了品牌声音、文案原则和设计标准。

视频表面是模型对比测试，实际在传递一个判断：**模型之间的差距远小于"有技能配置"和"没有技能配置"之间的差距。**

## 02 核心判断：视频真正想讲的不是模型选型

视频做了一个三组对照实验：同一份产品描述，分别喂给Claude Opus 4.5（带Frontend Design Skill）、Gemini 3 Pro（AI Studio）、以及Gemini 3 Pro（Antigravity IDE），看哪个产出最好。

但对比结果本身不是重点。重点是对比暴露出的问题：

**大多数人的AI建站流程缺了关键一步——在提示模型之前，先为模型建立上下文。**

这个"上下文"包含三层：

1. **品牌声音**：你说话的方式、你的受众期待什么语感、你拒绝什么样的表达
2. **文案框架**：你的落地页遵循什么结构（Hero → 痛点 → 方案 → 价值堆叠 → 社交证明 → CTA）
3. **设计标准**：你拒绝什么风格（典型的AI渐变、emoji、千篇一律的插画）

没有这三层，你给模型再多的提示，它也只能返回"统计平均"的产出——好看但没个性，完整但没灵魂。

视频的核心判断可以收束为一句话：**前置工作的质量决定了AI输出的上限，模型选择只影响你到达上限的速度。**

## 03 概念澄清：先把关键名词讲准确

### Claude Skills（技能系统）

- **它是什么：** Claude Code中的一组可安装的指令集。技能本质是一段长提示词，定义了模型在执行特定任务时应遵循的原则、约束和风格。
- **它解决什么问题：** 让模型在每次执行同类任务时自动参考同一套标准，而不是每次从零开始。
- **它不是什么：** 不是插件，不是API，不是独立的模型能力。它不会改变模型的推理能力，只是给它更好的上下文。
- **和普通提示词的区别：** 普通提示词是一次性的，你换一个对话就没了。技能是持久化的，每次执行相关任务时自动加载。
- **例子：** Frontend Design Skill 告诉Claude"避免典型AI设计风格，使用生产级设计标准"，每次你让它建页面时，这条指令自动生效。

### Frontend Design Skill

- **它是什么：** Anthropic官方团队构建的一个技能，专门指导Claude生成专业级前端设计。
- **它解决什么问题：** 避免AI生成页面的同质化——同样的渐变、同样的字体、同样的布局。
- **安装方式：** 两行命令。先添加Anthropic插件市场，再安装技能。具体见第06节。

### Elevated Direct Response（高级直接响应）

- **它是什么：** 一种文案哲学，结合了直接响应营销（明确的痛点刺激、清晰的价值主张、强硬的CTA）和品牌调性（不廉价、不油腻、不喊口号）。
- **它解决什么问题：** 大多数小企业主的文案走两个极端——要么是空洞的品牌话语（"赋能创新"），要么是过度的销售话术（"限时优惠"）。高级直接响应找中间路线。
- **它不是什么：** 不是传统品牌广告，不是硬广，不是"内容营销"那种只求关注不求转化的方式。
- **例子：** Cody Sanchez的风格是"反常识教育者"——先用一个违反直觉的观点抓住你，然后给出实用方案。Alex Hormozi的风格是"无法拒绝的报价"——把价值堆叠到你觉得自己不买就亏了。两者都是直接响应，但都不廉价。

### Vibe Building

- **它是什么：** 从Vibe Coding延伸出来的概念——不只是用AI写代码，而是用AI完成整个产品构建栈：编码、设计、文案、原型、部署。
- **它解决什么问题：** 描述一种新现实：非技术创始人可以在一个工具内完成以前需要设计师、开发者、文案三方协作的全部工作。
- **它和相关概念的区别：** Vibe Coding只指写代码的部分；Vibe Building覆盖全栈——设计、文案、产品逻辑、部署都包括。

### Antigravity

- **它是什么：** Google推出的agentic IDE，基于VS Code构建。
- **它解决什么问题：** 提供深度浏览器集成——通过Chrome扩展，IDE可以直接访问DOM、读取控制台输出，减少调试时的手动复制粘贴。
- **它不是什么：** 不是Cursor的替代品（至少目前不是），两者的核心编辑体验相似，差异在于与Google生态的集成深度。

## 04 整体框架：AI辅助产品构建的三层配置

```
┌─────────────────────────────────────────────┐
│           第三层：产出层                      │
│   一次提示 → 专业级落地页/原型/应用          │
├─────────────────────────────────────────────┤
│           第二层：技能层                      │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
│  │品牌声音   │ │文案框架   │ │设计标准      │ │
│  │Skill     │ │Skill     │ │Skill         │ │
│  └──────────┘ └──────────┘ └──────────────┘ │
├─────────────────────────────────────────────┤
│           第一层：研究层                      │
│  研究行业标杆 → 提炼文案原则 → 喂入自己样本  │
└─────────────────────────────────────────────┘
```

**第一层（研究层）** 是基础。你用AI工具（如Perplexity MCP）研究你所在领域的头部玩家：他们怎么写文案、怎么定位产品、怎么和受众沟通。从这些研究中提炼出可复用的原则。

**第二层（技能层）** 是核心。把第一层的研究成果，加上你自己写作风格的样本，转化为Claude Code中的技能文件。这些技能在每次任务中自动生效，不需要重复提示。

**第三层（产出层）** 是结果。有了技能层的支撑，一次简洁的提示就能产出专业级结果。没有技能层，十次提示也到不了同样的质量。

**关键洞察：** 大多数人直接跳到第三层，把详细的描述硬塞进提示词，然后抱怨模型输出平庸。问题不在模型——是你没给它足够好的上下文。

## 05 关键机制：Claude Skills到底是怎么运行的

### 输入

一个技能文件，本质是一段结构化的Markdown文本。内容包括：
- 任务定义（这个技能用于什么场景）
- 原则列表（应该遵循什么，应该避免什么）
- 风格示例（好的输出长什么样）
- 约束条件（硬性规则，不可违反）

### 中间处理

当你在Claude Code中发起一个任务（比如"帮我建一个落地页"），模型执行流程：

1. **匹配技能：** 根据任务类型，自动加载相关技能（如Frontend Design Skill）
2. **合并上下文：** 技能内容与你当前的提示词合并，形成完整的指令
3. **优先级排序：** 技能中的约束优先于模型默认行为。比如技能说"避免紫色渐变"，模型会遵守这条规则而不是使用默认的AI设计风格
4. **生成输出：** 在技能约束的框架内生成结果

### 输出

带有你定义的品牌声音、文案风格和设计标准的产物——落地页、原型、文案等。

### 为什么要这样设计

如果没有技能系统，你每次对话都要重新描述"我不要紫色渐变""我的品牌声音是X""CTA要强硬但不要太销售化"。技能系统把这些重复指令固化下来，让模型每次都从同一套标准出发。

### 代价

- **前期投入：** 需要花时间研究、提炼、测试、迭代。一个品牌声音技能的建立不是5分钟能完成的
- **维护成本：** 品牌在进化，技能也要更新。如果技能中的描述已经不符合你当前的风格，输出会偏离
- **过度约束风险：** 如果技能写得太死，模型可能丧失灵活性，输出变得机械

### 适合/不适合的场景

- **适合：** 重复性高的任务（落地页、邮件文案、产品描述），风格一致性要求高的场景
- **不适合：** 一次性探索性任务，需要AI发挥创造力的头脑风暴阶段

## 06 方法拆解：从零搭建AI辅助产品构建体系

### 步骤一：研究行业标杆

**目标：** 从你所在领域的头部玩家身上提炼文案和定位原则。

**具体动作：**
1. 在Claude Code中配置Perplexity MCP（或其他搜索工具）
2. 给出指令：`研究[你的领域]中3-5个最成功的玩家，分析他们的文案风格、产品定位、受众沟通方式，提炼可复用的原则`

**判断标准：** 你应该得到3-5条清晰的风格原则，每条有具体出处。比如"Cody Sanchez：反常识教育者——用违反直觉的开场吸引注意，再给出实用方案"。

**常见坑：**
- 不要只研究直接竞品，要研究同样受众群体、不同品类的成功案例
- 不要只看表面风格，要分析底层逻辑——为什么这种方式有效

**产出物：** 一份行业文案原则清单（3-5条）

### 步骤二：定义你的品牌声音

**目标：** 让AI能用你自己的方式说话，而不是生成通用的营销文案。

**具体动作：**
1. 收集5-10篇你自己写过的内容：推文、邮件、视频脚本、博客文章均可
2. 给Claude Code指令：`分析这些内容的语言风格，提炼出我的品牌声音特征`
3. 将结果整理成一份Voice Skill文档，包含：核心语感描述、应该使用的表达方式、应该避免的表达方式、3-5个典型句式示例

**判断标准：** 把Voice Skill给一个不了解你的人看，他能否用这种风格写出一段你认可的文字？

**常见坑：**
- 不要把品牌声音等同于"友好"或"专业"这种空泛描述——要具体到句式和用词
- 不要只描述你想要什么，也要描述你拒绝什么。反面约束有时比正面指引更有效

**产出物：** Voice Skill文件，存入Claude Code技能目录

### 步骤三：构建文案框架技能

**目标：** 将高级直接响应原则转化为可执行的落地页结构。

**具体动作：**
1. 基于步骤一的研究，定义你的"Elevated Direct Response"原则
2. 建立落地页架构：Hero区（核心价值主张）→ 痛点刺激（问题描述 + 放大）→ 方案呈现 → 价值堆叠（让报价难以拒绝）→ 社交证明 → 转变叙事（再次强化核心转变）→ 次要CTA → FAQ
3. 将这个架构写成Landing Page Skill文件

**判断标准：** 按这个技能生成一个落地页，它的文案是否同时满足：（a）有明确的痛点和CTA；（b）不油腻、不喊口号、不像硬广

**常见坑：**
- 最大的坑：**只关注设计不关注文案。** 页面好看但文字空泛，转化率不会好。老式的纯文字长销售信，排版简陋但文案精准，照样能转化。内容就是UX。
- 不要让价值堆叠变成功能列表——每个价值点要和受众的痛点直接关联

**产出物：** Landing Page Architecture Skill文件

### 步骤四：安装Frontend Design Skill

**目标：** 让Claude生成的设计避免"AI同质化"。

**具体动作：**
1. 在Claude Code终端输入第一行命令，添加Anthropic插件市场
2. 输入第二行命令安装技能：`/install-frontend-design@claude-code-plugs`
3. 验证安装：建一个简单落地页，检查设计风格是否明显不同于默认AI输出

**判断标准：** 生成的页面是否避开了紫色渐变、emoji堆叠、千篇一律的插画风格？是否看起来像真实产品的页面？

**常见坑：**
- 技能安装后不是万能的——它给设计设定了底线，但上限仍然取决于你的文案和产品逻辑

**产出物：** Frontend Design Skill已安装并生效

### 步骤五：测试与迭代

**目标：** 用一条简洁提示测试技能配置的效果。

**具体动作：**
1. 写一段产品描述（2-3句话），包含：目标用户、核心痛点、解决方案
2. 发给Claude Code，只说"帮我建一个转化优化的落地页"
3. 检查输出：文案是否用了你的品牌声音？设计是否避开了AI同质化？落地页架构是否完整？

**判断标准：** 如果一次提示的产出已经达到"可以直接用于MVP"的水平，配置成功。如果还需要大量修改，回到步骤二和三检查技能定义是否足够具体。

**产出物：** 一个可用的落地页HTML文件

## 07 案例讲解：Estate Clear——遗产管理家庭仪表板

### 场景背景

遗产执行人（estate executor）面临一个普遍问题：家属不断打电话、发短信问"爸爸的遗产进展怎么样了"。律师按小时收费，每次来回沟通都在烧钱。整个过程可能持续一年以上，对家属来说是一个黑箱。

### 遇到的问题

需要一个产品，让执行人能在一个仪表板上发布更新、共享文档、追踪进度，同时让家属获得通知而不是反复询问。简单说：给遗产管理做一个DoorDash式的实时追踪界面。

### 按框架如何处理

**研究层：** 这类垂直场景的核心问题是信息不对称。参考Carta（公司融资和财务管理平台）和家庭办公室产品——它们解决的是同一类问题：让复杂的专业流程对非专业人士透明化。

**技能层：** 使用Frontend Design Skill（避免AI同质化设计）+ 品牌声音技能（克制、专业、安抚性——遗产管理不是令人兴奋的事，不需要激进的销售话术）。

**产出层：** 一条简洁提示："我想为遗产管理创业公司创建一个转化优化的落地页。"

### 每步怎么做

**落地页（一次提示）：**

Claude Opus 4.5 产出了：柔和色调的Hero区、清晰的痛点描述、功能展示、定价卡片。整体风格克制、专业，没有紫色渐变和emoji。Gemini 3 Pro 产出了类似的页面，但额外加入了AI功能（"让AI帮你写更新"），风格更活泼但不够稳重。

**可点击原型（二次提示）：**

Claude Opus 4.5 构建了完整的仪表板原型：家庭视图、进度追踪、最近活动、文档存储、里程碑时间线。风格与落地页一致。多页面子视图（更新、文档、里程碑）都已实现。Gemini 3 Pro 产出了更偏社交风格的界面（类似动态流），AI集成功能可用，但产品深度不够——更像是一个信息发布板而非管理工具。

**Antigravity路径：**

Gemini 3 Pro 在Antigravity中先调用AI图像生成工具创建了一个高保真设计稿，再基于稿子构建HTML。工作流更像真实团队：先出视觉稿确认方向，再写代码。但最终页面的设计基础度较高，不如AI Studio版本。

### 最终结果

三个模型/环境都能产出MVP级别的产出。差异在于：

| 维度 | Opus 4.5 + Skills | Gemini 3 Pro (AI Studio) | Gemini 3 Pro (Antigravity) |
|------|-------------------|--------------------------|----------------------------|
| 设计精致度 | 高，风格一致 | 中高，更活泼 | 中，偏基础 |
| 产品深度 | 深，思考了完整工作流 | 中，AI功能有趣但深度不够 | 中，图像稿有价值但实现一般 |
| AI创意 | 保守但扎实 | 主动加入AI功能 | 利用图像生成做视觉稿 |
| 一次提示完成度 | 高 | 高 | 中 |

### 说明了什么

模型之间的差距是真实存在的，但差距的量级远小于"有技能配置 vs 没有技能配置"的差距。Opus 4.5产出了最精致的结果，很大程度上是因为Frontend Design Skill在起作用。如果你把同样的技能配置给其他模型，差距会缩小。

## 08 常见误区

**误区一："模型决定一切，选对模型就行了"**
- 为什么错：模型决定的是能力上限，但你能不能到达上限取决于怎么用。一个没配置技能的Opus 4.5，产出可能不如一个配置充分的Sonnet。
- 正确理解：模型是引擎，技能是导航。没有导航，引擎再强也开不到目的地。
- 应该怎么做：先建立技能体系，再选模型。技能体系可跨模型复用。

**误区二："AI设计的问题靠更多设计提示来解决"**
- 为什么错：视频中的两个主持人都明确指出——大多数人vibe coding产出转化率低，核心问题不是设计，是文案。老式纯文字长销售信转化率比精美的AI页面高，因为文案精准。
- 正确理解：内容就是UX。文字是内容的主体，设计是内容的容器。
- 应该怎么做：先投入时间建立文案技能，再优化设计技能。

**误区三："技能就是更长的提示词，没什么特别的"**
- 为什么错：普通提示词是一次性的、易遗忘的、不可复用的。技能是持久化的、自动加载的、跨项目一致的。这意味着你不用每次对话都重新描述你的品牌声音和设计标准。
- 正确理解：技能是你和AI之间的"长期记忆"，提示词是"短期对话"。
- 应该怎么做：把反复出现的指令沉淀为技能，只在提示词中放这次任务特有的信息。

**误区四："只测一次就知道哪个模型好"**
- 为什么错：一次对比只能说明在特定提示、特定场景下的表现。在第1次提示和第25次提示之间，排名可能完全反转。
- 正确理解：模型评估需要多轮、多场景、多提示长度的测试。一次对比的价值在于暴露差异维度，不在排名。
- 应该怎么做：把一次对比当作发现问题的工具，不是下结论的依据。

**误区五："要选一个最好的模型，其他都不用"**
- 为什么错：视频中的实践者明确说，他的日常工作流是Claude做主力（workhorse），Gemini/GPT做顾问（advisory）。不同模型在不同任务上有不同优势。
- 正确理解：多模型协作 > 单模型依赖。主力模型处理主要构建任务，顾问模型提供第二视角和创意发散。
- 应该怎么做：建立一个主模型 + 1-2个顾问模型的工作流。遇到疑难bug时，用顾问模型提供"外部视角"。

**误区六："Antigravity比Cursor更好（或反之）"**
- 为什么错：两者都是VS Code fork，核心编辑体验相似。真正的差异在于生态集成——Antigravity深度整合Google全家桶（Chrome调试、AI图像生成、部署），Cursor生态更开放但Google集成弱。
- 正确理解：选IDE不是选"更好"，是选哪个生态更适合你的技术栈。
- 应该怎么做：如果你重度依赖Google生态（Firebase、Google Cloud等），试试Antigravity。否则Cursor目前生态更成熟。

**误区七："AI生成的内容不需要人工优化"**
- 为什么错：视频中的落地页，两个主持人都指出了需要改进的地方：Opus 4.5的页面缺少社交证明和明确的顶部CTA；Gemini的AI功能有趣但需要验证是否用户真的需要。一次提示是起点，不是终点。
- 正确理解：AI产出的是80分的初稿，你需要补上最后的20分——尤其是社交证明、CTA优化和文案微调。
- 应该怎么做：把AI产出当作高起点初稿，而不是最终产品。预留迭代轮次。

## 09 实战清单

### 立即能做

1. **在Claude Code中安装Frontend Design Skill。** 两行命令，5分钟内完成。用它建一个简单落地页，感受和默认输出的差异。
2. **收集5篇你自己写过的内容。** 推文、邮件、博客均可。这是定义品牌声音的原材料。
3. **列出3-5个你所在领域的标杆人物/品牌。** 标注你最欣赏他们的什么——文案风格、定位方式、还是视觉呈现。
4. **检查你最近一个AI生成的落地页：文案是否有明确痛点刺激和CTA？** 如果没有，问题在文案不在设计。

### 一周内能做

5. **用Perplexity MCP（或手动搜索）研究步骤3中列出的3-5个标杆。** 提炼每家的核心文案原则，形成一份清单。
6. **把你的写作样本喂给Claude，让它提炼你的品牌声音特征。** 输出一份Voice Skill文档草稿。
7. **基于行业研究 + 你的品牌声音，写一份Elevated Direct Response原则文档。** 包含：你的核心文案风格、你拒绝的表达方式、你的落地页架构。
8. **用完整的技能配置重新生成之前那个落地页。** 对比有技能和没技能的输出差异。

### 长期要沉淀

9. **为每个重复性任务建立一个技能文件。** 落地页、邮件文案、产品描述、社交媒体——各自独立的技能，各自独立优化。
10. **建立一个多模型协作工作流。** 明确哪个模型做主力，哪个做顾问，什么情况下切换。
11. **每季度审查一次技能文件。** 品牌在进化，技能也要更新。删除过时的约束，补充新的原则。
12. **积累一个"反面案例库"。** 记录AI生成的不合格产出，标注问题出在哪个技能缺失上。这是技能迭代的最佳输入。

## 10 总结

AI编码模型的能力已经到了一个临界点：非技术创始人可以用一条提示词生成可演示的产品原型。但能力的民主化不意味着结果的民主化——同样的模型，在不同人手里产出天差地别。

视频通过三组对照实验展示了这个差距的来源。Claude Opus 4.5在落地页设计和原型构建上表现最精致，Gemini 3 Pro在AI功能创意上更激进，Antigravity在视觉工作流上提供了不同的思路。但这些差异是次要的。

主要差异来自技能配置。当你为模型建立了品牌声音、文案框架和设计标准三个层次的上下文，一次简洁提示就能产出专业级结果。当你跳过这些前置工作，模型只能返回统计平均的产出——没有个性、没有穿透力、没有转化力。

特别值得记住的是：**文案比设计更关键。** 一个排版简陋但文案精准的页面，转化率高于一个设计精美但文字空泛的页面。内容就是UX，文字是内容的主体。

最后，不要把模型选型当成最重要的事。建立技能体系，然后选一个用得顺手的模型做主力，留一两个做顾问。模型会迭代，技能会积累。技能才是你的复利资产。
