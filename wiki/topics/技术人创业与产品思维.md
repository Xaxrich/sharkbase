# 技术人创业与产品思维

## 核心主张
技术人做产品最大的障碍不是技术能力不足，而是**认知陷阱**——把"代码优雅"等同于"商业价值"，在自己脑子里的假环境优化，而非真实环境中的探索。这个陷阱不只是产品领域的问题，在 AI 训练中同样存在：环境偏见让模型记忆对手而非学习策略，就像技术人记忆"完美产品该长什么样"而非学习"用户实际需要什么"。

## 综合分析

### 认知陷阱：在自己的脑子里优化

来自 [[BV1SqDcBCEwW-关于一人公司也就是OPC的业务思考]] 的核心论据：技术人普遍存在"造完美轮子"的执念——代码优雅、架构清晰、测试覆盖面面俱到。这是学校教育训练的标准，但在商业世界里，标准只有一个：能运行、能用。UP主觉得28个扣子工作流+飞书文档"拿不出手"，咬咬牙发出去，首月变现1.2万。过度准备的本质是害怕真实反馈的"怂"。

来自 [[BV1D9ojBzEAd-将小模型训练成特定领域大师]] 的跨领域映射：RLVR 训练中的"环境偏见"问题和产品思维中的认知陷阱是同构的。Deepset 工程师发现 minimax 算法在多个最优走法中总是选第一个，导致模型实际上在记忆特定对手的走法，而非学习通用策略——模型以为自己在"学习下棋"，其实在"记忆一个特定对手"。技术人以为自己在"做产品"，其实在自己脑子里记忆"完美产品该长什么样"——两者都是在假环境中的优化，而非真实环境中的探索。

### 做减法：跨领域的元模式

**MVP 思维**（来自 [[BV1SqDcBCEwW-关于一人公司也就是OPC的业务思考]]）：不要等产品完美再上线。可以是一份文档、一个咨询、一个半成品demo，只要能解决问题、用户接受、收到钱，就是 MVP。用户不勤奋，只想用不想学——产品必须操作简单、使用成本低。

**克制式设计**（来自 [[BV1Y4oLBuEu6-吃透Claude-Code核心源码]]）：Claude Code 不断收缩工具暴露量（52→~20个），激发模型自身能力而非堆工具。这与 MVP 的"砍功能"是同一逻辑：约束产生聚焦，聚焦产生突破。

**RLVR 环境设计**（来自 [[BV1D9ojBzEAd-将小模型训练成特定领域大师]]）：可控的对手技能（不是最强也不是最弱）、确定性种子（减少噪声）、分层采样（平衡对手多样性）——每一个设计决策都是在"做减法"：去掉不必要的复杂性，让学习信号更清晰。

**元模式**：三者都是"减少预设、增加反馈"——MVP 减少产品预设增加市场反馈，Claude Code 减少工具预设增加模型自主决策，RLVR 减少环境噪声增加学习信号质量。详见 [[MVP思维]] 的深层联系部分。

### "营销 > 产品"需要批判性理解

来自 [[BV1SqDcBCEwW-关于一人公司也就是OPC的业务思考]] 的观点：在目前环境下，营销往往大于产品本身。50页完美商业计划书 vs 丑陋但已有用户的demo——投后者。

但这个说法需要补充：产品本身可以成为营销载体。Stripe 的 API 设计优雅到开发者自发传播，Notion 的产品体验本身就是增长飞轮。"营销 > 产品"在0→1阶段成立（先验证方向），但在1→10阶段可能翻转（产品力成为护城河）。

## 仍然开放的分歧

1. **产品什么时候从"够用就行"升级到"必须打磨"？** MVP 验证后的迭代路径是什么？从"丑陋demo"到"可持续产品"的转折点在哪？
2. **一人公司的规模化瓶颈** — 当"不勤奋的用户"需要更多服务时，超出一人的交付能力，如何破局？
3. **精准流量 vs 爆款** — UP主首月400粉丝变现1.2万证明精准流量有效，但这是否可持续？规模化的路径是什么？

## 我的立场

技术人认知陷阱的根源是**缺乏真实环境反馈的训练**——学校只训练"在给定需求下写出好代码"，不训练"发现什么需求值得写"。这和 SFT 只训练"模仿示例"不训练"探索更优策略"是同一个问题。解法也是一样的：从 SFT 转向 RLVR——从"在自己脑子里优化"转向"放到真实环境中试错"。
