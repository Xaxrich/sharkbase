# 异步Agent范式

## 定义
与 AI 的交互模式从"发 prompt → 等回复 → 再发下一个"的同步模式，转向"交办任务 → 去做别的事 → 回来看结果"的异步模式。Agent 长时间自主运行，人在关键决策点介入审查。

## 为什么重要
这是非技术用户使用 AI 的下一个关键解锁。当前大多数人用 Chat 类产品停留在同步对话模式——AI 几分钟内回复，用户立即回应。但真正的生产力来自异步模式：让 Agent 跑几十分钟甚至一小时做深度研究、数据分析、文档撰写，人只需在完成后审查和调整。这根本性地改变了人与 AI 的协作关系——从"实时对话"到"交办-审查"。

Felix（Anthropic）用"搜索框泛化"类比：未来可能不需要为每个场景建单独的输入框，而是走向少量通用入口，背后的 Agent 自主决定如何完成任务。

## 我的判断
- **赞同**：异步范式是正确的方向。同步模式受限于"几分钟内必须给出答案"的约束，导致 AI 只做浅层工作。异步模式释放了 Agent 的深度工作能力——竞品分析、日历审计、全文档校对，这些任务天然需要长时间运行。
- **质疑**：异步模式要求用户信任 Agent 的中间决策。同步模式下用户可以实时纠偏，异步模式下 Agent 可能沿着错误方向跑了30分钟才发现。审查成本和信任成本是隐形的。
- **补充**：Felix 提到的 Excel 类比很重要——power user 往往更愿意留在通用工具中而非迁移到特化产品，即使后者理论上更高效。这意味着异步范式的采纳可能比预期慢，因为用户习惯是最大的切换成本。
