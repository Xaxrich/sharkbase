# Ctx2Skill从上下文提技能：从视频到可复用 Agent 工程方法

## 一句话导读
Ctx2Skill 关注模型面对一份陌生复杂资料时，能否零标注地通过自博弈把资料里的规则、流程和约束提炼成可复用技能。

## 适合谁看
- 正在做 Agent、工具调用、Skill 库或长期记忆系统的开发者。
- 需要把论文方法转成工程决策和评估标准的产品/研究同学。
- 想理解 Agent “自进化”到底发生在模型、外壳、技能还是数据层的人。

## 读完你会获得什么
- 能解释 `Ctx2Skill从上下文提技能` 解决的核心 Agent 工程问题。
- 能区分它和同系列其他 Agent 进化路线的不同位置。
- 能把论文思路转译为自己的 Agent / Skill / Harness 系统设计检查项。
- 能识别这一路线的适用边界和潜在风险。

## 核心框架
- 这里的 context 是外部复杂资料，不只是聊天窗口。
- 目标不是从资料中找答案，而是先学习资料里的新规则，再解决后续任务。
- Challenger 根据资料出探测任务和 rubrics，Reasoner 带当前技能答题，Judge 按 rubrics 判分。
- 失败题用于更新 Reasoner 技能，成功题用于提升 Challenger 出题能力。
- 技能是自然语言操作手册，不更新参数。

## 01 普通总结为什么不够

- 复杂资料中包含格式约束、流程顺序、例外条件和角色规则，单次总结不知道漏了什么。
- 没有反馈，模型写出的技能是否能支撑任务无法验证。

## 02 自博弈闭环

- Challenger 负责出有区分度的任务，不只是把题变难。
- Reasoner 使用当前技能答题，暴露资料理解缺口。
- Judge 只按 rubric 严格判定，失败再反推缺失技能。

## 03 适用场景

- 产品手册、游戏规则、实验记录、网页材料、报告和复杂对话都可以视作资料源。
- 它适合把一次性上下文变成后续可重复使用的资料专属技能。

## 常见误区
- 不要把“保存更多历史”直接等同于“Agent 学会了经验”。经验必须变成可检索、可验证、可控制的表示。
- 不要只看单次成功案例。Agent 进化需要跨样本证据、失败归因和回归验证。
- 不要忽略运行成本。技能库、harness 日志、动态数据和测试沙箱都会引入额外 token 或执行成本。
- 不要把自动更新直接上线。共享技能和 harness 改动尤其需要灰度、回滚和审计。

## 延伸问题
- Challenger 如何避免出偏题或伪难题？
- Rubric 自动生成的可靠性如何校准？
- 资料更新后技能如何失效和重建？
