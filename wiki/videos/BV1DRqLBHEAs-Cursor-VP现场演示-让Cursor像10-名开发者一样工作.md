# Cursor VP现场演示：让Cursor像10名开发者一样工作

## 一句话摘要
Cursor 团队成员 Le 现场展示如何用 AI Agent 并行处理开发任务，核心方法论是「短对话、多 Agent、让系统自纠错」。

## 核心观点

- **每个任务开新对话**，不要在一个聊天里无限追加——上下文窗口是 Agent 的工作记忆，超过 80% 就开始退化
- **提示词不需要复杂**，直接说需求 + 明确引用文件即可，关键是让 Agent 能读取 lint/test 输出来自我修正
- **规则文件和自定义命令**是把个人工程经验固化成可复用配置的手段
- **Agent 不只活在编辑器里**——CLI、Slack、Web、CI/CD 都可以触发，形成自动化流水线
- **个人软件时代**：代码边际成本趋零后，一次性使用的调试工具、迁移可视化界面都值得造

## 详细笔记

### 多 Agent 并行工作模式

Le 展示了他一天的工作记录：20 个独立 Agent 对话，每个处理一个离散任务（3-75 行变更不等）。

典型模式：
1. 给出简短直接的指令（如"添加事件追踪，当 MP 的添加到 Cursor 按钮被点击时"）
2. Agent 读文件、思考、修改、读 lint 输出、自我修正
3. 确认变更通过所有检查后完成

关键前提：项目必须有 TypeScript + Lint + 格式化 + 测试，这样 Agent 才能读懂自己的输出并纠错。

### 上下文窗口管理

这是视频反复强调的核心陷阱：

- 上下文窗口 = Agent 的工作记忆，对话越长越容易遗忘早期内容
- Cursor 在上下文达 100% 时会自动摘要并继续，但 80-90% 时质量已经开始下降
- 早期研究显示，长上下文任务（即使是号称百万 token 的模型）质量会显著衰减
- **结论：每个新任务开新对话，不要在同一个聊天里无限追加**

这解释了很多开发者从 Vibe Coding 转向生产应用时"Agent 变笨"的感觉——不是模型被偷偷降级，而是上下文被垃圾塞满了。

### 规则文件（.cursorrules）

Le 展示了两类规则：

**写作规则**：
- 语气和风格指南
- 禁用词列表（删掉"mission critical"、"seamless"等营销套话）
- LLM 输出模式黑名单（"it's not just X, it's Y"、"once you see it you can't unsee it"等 AI 常用句式）

**自定义命令**：
- 代码审查命令：离线场景处理、加载状态、测试质量、认证变更触发安全审查、缓存机会等检查项
- 可根据项目定制：安全审查、vibe check 等

### Bug Bot 与 CI/CD 集成

Cursor 把内部用了近一年的代码审查 Agent 产品化为 **Bug Bot**：
- 在 GitHub PR 上自动评论，指出遗漏（如国际化文档缺语言）
- 可通过 CLI 在 GitHub Actions 中运行，实现自动化：
  - 每次 PR 合并后自动更新文档
  - CI 失败时自动修复并推送 commit
  - 定期扫描安全漏洞

### 多入口触发 Agent

Agent 不局限于编辑器 GUI：

- **Slack**：在手机上收到 bug 报告，直接在 Slack 中 `@cursor` 让 Agent 调查修复，回来审阅 PR 即可
- **Cursor Agents Web**：在浏览器中启动 Agent，在云端安全沙箱运行，适合移动场景
- **CLI**：终端中运行，支持 YOLO 模式（自动执行所有命令），适合高级开发者

### Linear 的零 Bug 策略

Linear 的流程：PM 报告 Bug → AI 分类 → 工程师让 Cursor 调查修复 → 自动开 PR → 接受变更。周转速度极快。Le 认为零 Bug 策略不仅是工程实践，也是市场定位——客户看到"零 Bug"会更倾向于选择你的产品。

### 个人软件与边际成本

代码边际成本趋零后出现的现象：
- **一次性调试工具**：为单个问题构建完整的可视化调试界面，用完即弃
- **迁移 AB 对照界面**：逐步对比两个版本的差异
- **垂直领域创业**：用 Cursor + 图像生成模型（如 Google Imagen）快速构建垂直应用

### 分发工程

Le 提出的概念：随着产品构建门槛降低，**分发能力**成为新的核心技能。过去的路径是 前端/后端 → 产品工程师，现在可能是 产品工程师 → 分发工程师。用个人软件作为分发工具（lead magnet），再转化为商业产品。

## 我的评注

- **赞同**：上下文窗口管理是最被低估的实践。很多开发者抱怨"AI 变笨"，实际上是自己把上下文塞废了。开新对话这个建议简单但极其有效。
- **赞同**：让 Agent 能读取 lint/test 输出实现自我修正，这是工程实践而非提示词技巧。基础设施决定 Agent 上限。
- **质疑**：视频对"零 Bug 策略"的描述过于乐观。Cursor 擅长修小 Bug（typo、缺失国际化），但复杂逻辑 Bug 仍需人类判断。把 Bug Bot 能力和"零 Bug"画等号有营销之嫌。
- **质疑**："分发工程"概念有价值但论证不足。Le 自己也说"还没想好怎么写成博客"，说明这个想法尚在萌芽阶段，视频里更多是直觉而非分析。
- **关联**：视频中的 Agent 并行模式与 [[AI驱动的产品工作流]] 和 [[上下文工程]] 高度相关。多 Agent 短对话的本质是把任务拆分到上下文窗口能可靠处理的粒度。
