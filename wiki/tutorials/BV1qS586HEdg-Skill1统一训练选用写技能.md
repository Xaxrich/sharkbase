# Skill1统一训练选用写技能：从视频到可复用 Agent 工程方法

## 一句话导读
Skill1 用同一个任务成败信号同时训练技能选择、技能执行和技能蒸馏，让外部技能库跟着 Agent 的行为一起进化。

## 核心框架
- 技能增强 Agent 不只要会执行，还要会选技能、会把新经验写成有价值的技能。
- 任务成功信号直接训练执行能力，长期技能效用训练重排选择。
- 蒸馏奖励关注当前成功是否超过已有候选技能的最高效用，避免重复写低增量技能。
- GRPO 同时覆盖查询、重排、动作序列和技能文本生成。
- 实验显示去掉技能库、选择或蒸馏都会显著降低表现。

## 01 为什么一个信号要拆三份

- 执行、选择和沉淀共同决定最终任务成败，用不同奖励可能导致目标不一致。
- Skill1 把最终任务结果分配给三个环节，使技能库本身成为训练对象。

## 02 技能生命周期

- 策略先生成自然语言查询，冻结编码器检索候选技能。
- 策略重排并选择一个技能，执行任务后复盘轨迹，生成新策略与适用场景。
- 只有成功轨迹蒸馏出的技能会入库，并受容量和效用淘汰约束。

## 03 边界与风险

- 技能库增长会增加训练成本。
- 自动积累技能可能带来审计难度和注入风险，高风险部署需要人类监督。

## 常见误区
- 不要把“保存更多历史”直接等同于“Agent 学会了经验”。经验必须变成可检索、可验证、可控制的表示。
- 不要只看单次成功案例。Agent 进化需要跨样本证据、失败归因和回归验证。
- 不要忽略运行成本。技能库、harness 日志、动态数据和测试沙箱都会引入额外 token 或执行成本。
- 不要把自动更新直接上线。共享技能和 harness 改动尤其需要灰度、回滚和审计。
