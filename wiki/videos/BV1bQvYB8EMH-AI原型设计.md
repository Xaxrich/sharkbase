# AI原型设计：用AI进行原型设计的正确方法

## 一句话摘要

Vibe Coding 适合快速实现，但在设计探索阶段存在五个关键缺口——识别并填补这些缺口，才能让 AI 原型设计真正发挥价值。

## 核心观点

- Vibe Coding 的线性工作流（prompt→迭代→prompt→迭代）天然缺乏设计探索空间，需要主动引入设计思维
- 第一个 prompt 决定方向，模糊的起点会导致大量 token 浪费且永远无法到达目标
- AI 原型设计需要支持发散思维：同时生成多个方案、并排比较、混合搭配
- 组件库 + 自定义指令的组合才能产生高质量、风格一致的 AI 生成设计
- 手动微调与 AI 模式之间的无缝切换是工具成熟度的关键指标

## 详细笔记

### Vibe Coding 的线性困境

Vibe Coding（无论是 Lovable、v0、Cursor 还是 Claude Code）遵循线性路径：prompt → 迭代 → prompt → 迭代。这对工程实现很高效，但作为产品设计工作流存在明显缺陷——缺少设计探索的余地。设计师需要的不是一条直线，而是能分叉、回溯、并排比较的树状结构。

### 五个设计缺口与解决策略

#### 缺口一：前置清晰度

问题：第一个 prompt 如果模糊，后续所有迭代都在错误方向上积累偏移，花大量 token 也难以纠正。

解决：在喂入第一个 prompt 之前，先用 GPT 澄清关键问题——目标用户是谁、他们的需求是什么、聚焦哪个用户流程。演讲者为此构建了多个 Custom GPT，针对不同场景（快速蓝天空原型 vs 深度交互式探索）使用不同 GPT。GPT 通过结构化问答生成一份"原型规格"（不是传统 PRD），打包为 code block，可直接粘贴到任何 AI 原型工具中。

#### 缺口二：追踪迭代

问题：设计过程不是线性的——你会分叉、回退、跳转，但大多数 AI 工具只提供线性对话历史，无法可视化这些分支。

解决：使用 Magic Patterns 的 Canvas 功能。每个设计探索作为独立预览窗口放在白板上，可以深入某一个方向的编辑器迭代，完成后自动同步回白板。少数 AI 工具提供此类功能。

#### 缺口三：发散思维

问题：设计需要同时探索多个方案并排比较，但大多数 AI 工具一次只生成一个结果。

解决：Magic Patterns 的 `/inspiration` 命令默认生成四个设计方案，可反复刷新获取更多。可以限定范围（选中某个组件再生成变体），也可以描述想要的改变方向（更紧凑、更易访问等）。

#### 缺口四：混合搭配

问题：方案 A 的导航栏 + 方案 B 的内容区 + 方案 C 的配色——实际设计经常需要从不同方案中取长补短。

解决：
- Magic Patterns：在 chat 中指定"用方案三的布局，加上方案一的某个组件"
- Subframe：直接拖拽组件——从一个设计选项中拖出组件放到另一个中，删除不需要的部分。Subframe 的心智模型更接近 Figma，而 Magic Patterns 更接近 Lovable

#### 缺口五：手动微调

问题：AI 生成的结果 80% 满意但需要微调——移动元素、调整间距、改 padding——然后又想回到 AI 模式继续迭代。

解决：
- Magic Patterns → 导出至 Figma 做最终调整（牺牲交互性，但符合已有工作流）
- Subframe → 在 Ask AI 模式和 Design 模式之间实时切换，设计模式类似 Figma 的属性面板，两个模式是集成体验而非割裂

### 去除 AI 味：组件库 + 自定义指令

AI 生成的设计往往长得很像——同质化的紫色渐变风格。解决方法是两层架构：

1. **自定义指令**（类似 Claude Code 的 CLAUDE.md）：用反向提示词（reverse prompting）——给 GPT 几张目标产品的典型截图，让它生成包含颜色、字体层级、间距、网格的设计系统指令
2. **组件库**：在 Magic Patterns 中重建目标设计系统的组件代理——从 Storybook 截取不同状态的截图，自动生成可复用的代码组件

两者缺一不可：组件库提供积木，自定义指令提供放置积木的原则。

### 工具选择建议

- **Magic Patterns**：适合设计探索阶段，心智模型简单，与 Figma 工作流兼容（导出到 Figma）
- **Subframe**：适合希望在一个平台内完成所有工作的场景，Figma 式编辑体验
- 演讲者个人更倾向 Magic Patterns，因为她的核心需求是设计探索，且深度使用 Figma

## 我的评注

- **赞同**：五个缺口的框架非常精准，尤其是"前置清晰度"——很多人低估了第一个 prompt 的决定性作用。用 GPT 先澄清需求再喂入原型工具，这个两步法成本低但收益极大
- **赞同**：组件库 + 自定义指令的双层架构是解决 AI 设计同质化的正确思路，本质上就是把设计系统知识注入 AI 的生成过程
- **质疑**：演讲者提到的工具生态（Magic Patterns、Subframe）变化极快，工具特性可能在数月内失效。核心方法论（五个缺口）有持久价值，但工具层面的建议需要持续验证
- **质疑**：整个讨论偏重工具操作层面的 workaround，缺少对更根本问题的讨论——AI 原型设计产出的设计方案是否真正经过了设计推理，还是只是风格变异？发散思维不只是生成更多方案，还需要评估框架
- **关联**：自定义指令的思路与 [[代码即最高保真]] 和 [[AI设计美学]] 直接相关——核心都是如何将设计约束系统化地注入 AI 生成过程，而非依赖一次性 prompt
