# 驾驭工程

## 定义
Harness Engineering（驾驭工程），指构建 AI Agent 时，除大语言模型本身之外的所有工程系统的总称——推理引擎、工具系统、记忆管理、安全约束、协作机制。Claude Code 是目前最佳的可参考实现。

## 为什么重要
驾驭工程解答了一个被忽视的问题：为什么同样用 GPT-4/Claude 的 API，有的产品体验极好，有的只是套壳聊天？差距不在模型，在 Harness。好的 Harness 让模型在约束中发挥最大能力，差的 Harness 要么不给模型任何工具（纯对话），要么塞太多工具和信息（模型迷失）。Claude Code 用 52 个工具经三层过滤后只给模型看 ~20 个的设计，就是"约束中激发能力"的典型。

这个概念的语义仍在快速演变——从测试领域的 test harness，到 OpenAI 论文的三大支柱（Engineering/Constraints/Garbage Collection），再到如今泛化为"模型以外的一切"。但不管怎么定义，Claude Code 的代码就是最好的参考实现。

## 我的判断
- **赞同**：Claude Code 的"克制式"设计哲学是对的。Agent 的能力瓶颈不在于工具多少，而在于模型能否在给定上下文中做出正确决策。工具越多、上下文越长，决策质量越差——这是反直觉但被反复验证的。
- **质疑**：当前对 Harness 的讨论过于聚焦 Claude Code 一个样本。不同场景（企业级多 Agent 协作 vs 个人助手 vs 代码生成）可能需要截然不同的 Harness 设计。一种模式不能统治所有。
- **补充**：Harness 最被低估的组件是 Garbage Collection（垃圾回收）。Claude Code 的 Auto Dream 机制——每24小时清理记忆、去重、解决冲突——决定了项目空间能否长期使用而不劣化。这和代码库需要定期重构、产品需要定期砍功能是同一个道理。

## 深层联系
- [[MVP思维]] — **这是知识库中最重要的跨领域共振**。驾驭工程的"克制式设计"和 MVP 思维的"不要等产品完美再上线"是同一思想的两种表达：**做减法 > 做加法**。Claude Code 不断收缩工具暴露量来激发模型能力，创业者不断收缩功能范围来验证核心假设。底层逻辑一致：约束产生聚焦，聚焦产生突破。
- [[RLVR训练范式]] — RLVR 的训练环境就是模型层面的 Harness：它定义了探索边界和奖励函数。环境设计得好（约束恰当）模型能学会大师级策略，环境设计得差（约束不当或噪声过大）模型连新手都不如。
- [[MCP Server]] — Harness 工具系统的核心互操作协议。Claude Code 的动态加载机制（按需发现而非预加载）体现了"克制"哲学在工具层的落地。
- [[规范驱动开发]] — 规范驱动开发是驾驭工程在"工作流层"的体现：规范就是系统级的 harness，用结构化流程约束 agent 的行为空间，替代人肉护栏的实时纠偏

### Claude Code 的同心圆架构

| 层次 | 名称 | 比喻 | 核心组件 |
|------|------|------|----------|
| 核心 | Model API | 大脑 | LLM 本身，被驾驭的对象 |
| 第一圈 | Query Engine | 神经系统 | ReAct循环、Prompt工程、记忆管理、Token管理 |
| 第二圈 | Tool System | 手脚 | 基础工具(52→~20)、MCP工具、Skills系统 |
| 第三圈 | Agent Collaboration | 团队协作 | SubAgent、ForkAgent、协调者、Team |
| 外围 | Security | 基础设施 | 权限、沙箱、防注入、审计 |

### 核心组件详解

**ReAct 循环**（Query Engine 的核心）
State 结构体维护 message list + tools list + 轮次/压缩/终止状态。循环流程：构建prompt → 请求模型 → 文本则退出，工具调用则执行 → tool result 追加 → 检查压缩 → 重复。关键认知：模型本身没有工具能力，框架负责执行。

**System Prompt 的静态分隔符策略**
从最静态（身份、规则）到最动态（git状态、日期）组装，最大化模型端 Token 缓存命中率。缓存命中的 token 价格仅十分之一。

**记忆管理三层**
1. 声明式记忆（system prompt 中声明"你有记忆系统"）
2. Extended Memory（stop hook 触发，自动从 message list 提取记忆）
3. Auto Dream（每24小时闲时触发，扫描+整合+去重+清理，实验性）

**Agent 协作五种模式**
通用SubAgent（空白起点，成本低）、专用SubAgent（预定义角色）、ForkAgent（克隆全上下文，利用服务端缓存）、协调者模式（只编排不执行）、Team模式（独立数字员工协作）。仅前两种开放。

**安全六大原则**
纵深防御、最小权限、安全默认、零信任模型输出、TOCTOU防御、企业可控性。核心：安全没有一招先，只能在每个漏洞点层层设防；永远不依赖模型判断来决定是否安全。
