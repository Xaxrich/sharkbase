# 30分钟精通OpenClaw（5个真实用例+设置+内存）

## 一句话摘要

OpenClaw 是一个开源的个人 AI 助手框架，通过本地部署 + 最小权限接入外部服务 + 可编辑的记忆文件系统，实现真正个性化且安全的私人助理体验。

## 核心观点

- OpenClaw 的核心价值在于"像跟朋友发消息一样让 AI 替你做事"，而非传统的指令式交互
- 安全性是个人 AI 助手的底线——独立账号、最小权限、绝不共享 bot，缺一不可
- 记忆系统是 OpenClaw 区别于普通 AI 产品的关键：人格、长期记忆、开放循环、张力追踪，全部由本地 .md 文件管理
- 用自然语言聊天就能完成 Cron 任务配置、API 接入、工具集成——大幅降低了自动化的门槛
- Google Workspace 集成虽然配置繁琐，但一旦完成，日历/文档/表格的读写能力让 bot 的实用性质变

## 详细笔记

### 安全设置五原则

1. **独立机器运行**：部署在专用 Mac Mini 或旧 MacBook 上，24/7 开机（可用免费 app 保活）
2. **独立账号体系**：Bot 使用自己的 Apple ID 和 Gmail，不共享主账号
3. **运行安全审计**：终端执行 `cloudbot security audit --deep`，自动加固
4. **最小权限**：只给 bot 读权限（如日历），写权限仅限指定文件（如共享的 Google Doc）
5. **绝不共享 bot**：不加入群聊、不发布到网站——有人因将 bot 接入公开的 vibe-coded 应用导致数据泄露

### 五个真实用例

#### 1. 日历管理

Bot 拥有自己的 Google Calendar，用户将自己的日历以只读方式共享给它。Bot 通过发送日历邀请来替用户创建事件。

工作流：用户发消息 → bot 搜索信息（如 Caltrain 时刻表）→ bot 在自己日历创建事件并将用户加为参与者 → 用户接受邀请。

关键设计：bot 不能直接写入用户主日历，而是通过邀请机制间接操作，保持安全边界。

#### 2. 文档与表格编辑

将特定 Google Doc/Sheet 通过共享赋予 bot 编辑权限。Bot 可以根据聊天指令向文档追加内容（如旅行计划），或向表格特定单元格写入数据（如内容日历更新）。

比起手动打开 ChatGPT 生成内容再复制粘贴，直接在聊天中让 bot 写入文档效率更高。

#### 3. 语音交互

Bot 可配置 TTS 引擎发送语音消息。免费方案 Edge TTS 提供 300+ 微软语音；付费方案有 ElevenLabs。用户通过 WhisperFlow 语音输入，bot 以语音笔记回复。

设置方式：直接在聊天中要求 bot 配置 Edge TTS，bot 自行完成 gateway 设置。

#### 4. 每日简报

通过 Cron 任务，bot 每天自动整合多个数据源生成简报：
- 天气
- 即将到来的日历事件
- 内容发布排期
- 关注领域的热门讨论（通过 Twitter 只读访问）
- 基于记忆和个人推文的个性化思考

用户可回复当日专注事项，bot 会在全天发送提醒。

#### 5. 周度洞察报告

Bot 每周发送邮件，包含：
- YouTube 视频数据（通过 yt-dlp 抓取公开数据）
- Substack 文章统计（bot 被加为管理员，通过浏览器抓取——因 Substack 无公开 API）
- 相似频道分析及内容创意建议

### Google Workspace 集成

配置步骤（由 bot 指导完成）：

1. 为 bot 创建独立 Gmail 账号，共享日历和指定文件
2. 在 Google Cloud Console 创建新项目
3. 逐个启用 API：Gmail、Calendar、Drive、Docs、Sheets、Slides
4. 配置 OAuth 同意屏幕（External 模式）
5. 创建 Desktop Application 类型的 OAuth 客户端
6. 下载 credentials JSON 文件，粘贴给 bot 完成剩余配置
7. 添加授权范围（Scopes）和测试用户

Google Cloud 界面体验差是主要痛点，但整个流程约 30 分钟，且可以截图让 bot 指导定位具体操作位置。

### 记忆系统架构

OpenClaw 的记忆和人格由本地 .md 文件管理，位于 `cloud/` 目录下：

| 文件 | 作用 |
|------|------|
| `identity.md` | Bot 的名字、风格标签 |
| `soul.md` | 人格、声音、价值观——bot 通过对话自行生成和迭代 |
| `memory.md` | 长期记忆：用户情况、目标、能力权限清单 |
| `heartbeat.md` | 每 30 分钟检查一次的定时任务文件 |
| `memory/` 目录 | 每日记忆笔记，bot 自动从当天对话中提取关键信息 |

**memory.md 的高级用法**：

- **Open Loops（开放循环）**：用户提到但未闭环的承诺或目标，bot 可在简报中提醒
- **Tensions（张力）**：用户公开表态与私下聊天中的矛盾，bot 帮助识别
- **Patterns（模式）**：bot 观察到的用户行为模式（如"被构建和自主性激发能量"）

**soul.md 的自定义**：用户可通过聊天指令调整 bot 的回复风格，如"不要用 AI 腔调""直接诚实""不使用 emoji""写主动语态减少模糊表述"。

## 我的评注

- **赞同**：最小权限 + 独立账号的安全模型非常务实。通过"邀请机制"而非直接写入权限来操作日历，是在便利和安全之间找到的好平衡。很多人会贪方便把主账号密钥直接交给 AI，这种做法迟早出事。
- **赞同**：记忆系统的设计理念值得学习——不是黑盒向量数据库，而是人可读、人可编辑的 .md 文件。这意味着用户对 bot 的"人格"拥有完全控制权，也意味着可以在 bot 行为异常时直接定位和修复。
- **质疑**：视频对"bot 自行配置一切"的描述过于乐观。Google Cloud 的 OAuth 配置涉及 Scopes 和测试用户等关键步骤，bot 的指导并不总是准确的——作者自己也承认跳过了两个必要步骤。对于非技术用户来说，这个流程仍然是门槛。
- **质疑**：每天让 bot 总结对话存入记忆文件，但没有提到记忆膨胀和遗忘机制。长期使用后，memory.md 和每日笔记会不断累积，可能导致 bot 的上下文被过时信息污染。
- **关联**：OpenClaw 的记忆架构与 [[个人操作系统]] 概念高度相关——它不只是一个工具，而是一个持续学习用户习惯和目标的系统。开放循环/张力/模式的框架，本质上是把 [[主动式Agent]] 的理念落到了个人助理场景。soul.md 的设计也呼应了 [[AI设计美学]] 中的主张：AI 的行为风格应该是用户显式定义的，而非默认的"讨好型助手"。
