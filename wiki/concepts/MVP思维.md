# MVP思维

## 定义
MVP（Minimum Viable Product，最小可行产品）思维：用最少功能和最低成本构建可验证的产品版本，快速投入真实环境获取反馈。核心不是"做什么"，而是"什么不做"。

## 为什么重要
MVP 思维的深层逻辑是：**人类对"什么有用"的预测能力远低于自己的估计**。你在脑子里优化一百遍，不如真实用户的一句反馈。硅谷那句"如果你对第一个版本的产品不感到羞耻，那你发布得太迟"不是鼓励粗糙，而是在说：过度准备的本质是逃避——害怕面对"没人要"的真实答案。

这个逻辑不只适用于产品。[[驾驭工程]]里 Claude Code 用克制式设计激发模型能力，[[RLVR训练范式]]里用环境约束而非完美示例训练模型——都是"减少预设、增加反馈"的同一思路。

## 我的判断
- **赞同**：技术人最大的认知陷阱就是"代码优雅=商业价值"。云途的AI之路的例子很典型——28个扣子工作流+几个飞书文档，首月变现1.2万，没有任何官网APP助理。用户买的不是优雅，是"能解决我的问题"。
- **质疑**："营销 > 产品"的说法过于绝对。有些领域产品本身就是最好的营销——Stripe 的 API 设计优雅到开发者自发传播，Notion 的产品体验本身就是增长飞轮。MVP 不等于"产品不重要"，而是"先验证方向再迭代产品"。
- **补充**：一人公司(OPC)是 MVP 思维的天然实践形态。资源有限倒逼你只做最核心的事，而"先免费再收费"（云途的策略）是最低成本的验证方式。但一人公司的规模化瓶颈很明确——当你需要"不勤奋的用户"也能用的时候，就超出一人的交付能力了。

## 深层联系
- [[驾驭工程]] — **做减法是跨领域的元模式**。Claude Code 不断收缩工具暴露量（52→~20）来让模型决策更精准，MVP 思维不断收缩功能范围来让核心假设更清晰。底层逻辑：约束产生聚焦，聚焦产生突破。两者的反面都是"做加法"——塞更多工具 vs 堆更多功能——结果都是主次不分、什么都做不好。
- [[RLVR训练范式]] — RLVR 说"不要给模型完美示例，让它在环境中试错"，MVP 说"不要等产品完美再上线，放到市场中验证"。两者都是**用环境反馈替代人类预设**。RLVR 的环境偏见问题也对应产品中的"你以为用户需要的 ≠ 用户实际需要的"——都是在自己脑子里的假环境优化，而非真实环境中的探索。
- [[MCP Server]] — MCP 的动态加载机制（按需发现而非预加载所有工具描述）也是 MVP 思维在工程上的体现：不给模型它不需要的信息，只在实际需要时才暴露。

### 关键案例

云途的AI之路的首个产品：最初定价免费→40元，28个扣子工作流源码+几个飞书文档，无官网/APP/助理，首月变现1.2万。精准流量胜过爆款——没有爆款视频，纯靠精准流量获客。

C端用户画像的关键洞察：不要把用户想得很勤奋。用户只想用不想学，产品必须操作简单、使用成本低。背后的原理再牛，用户不在乎——"按哪个键能出图搞定"才是用户关心的。
